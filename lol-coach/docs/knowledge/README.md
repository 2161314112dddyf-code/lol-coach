**先给玩家此刻能做的动作，再看能往前判断多远。** 一步做完确实会改变下一步，就讲清做成或受阻时怎么接。若下一步取决于还没看见的兵线或敌人动向，可以停在当前动作，说明哪条信息值得等、何时再判断。

## 击杀后，不能只说“推线然后走”

以下是条件示例，不是某场回放的事实。

1. **交手刚结束。** 先看自己能否继续行动、谁还在、双方兵线和清线能力。比较送塔、保留来线、立即回补。敌辅死亡也不证明敌方射手不能挡线。
2. **选择了送塔。** 希望取得回补或离线空隙。兵真正进塔且能安全离开，才进一步比较回城、点塔、短走。若下一波在塔外接住、敌人来人或状态不够，就重新比较补推与退出。
3. **已经进塔。** 再看塔下残兵、双方增援和对手怎样处理。可能重新交汇，也可能开始回推或继续前压。回补后要从实际线形选接线与保护，不能直接写“下波必然安全回推”。

这条链上的击杀、送塔、买装和队友接应，只有取得当前证据后才升级为事实。旧计划里“预计会发生”不等于下一帧已经发生。

## 已怎样接入 Agent

- 本地数据为 [coaching_handbook_v1.json](../../lol_coach/profiles/coaching_handbook_v1.json)，含24张卡、32份来源档案、适用前提、分支、反例、下一触发与版本。扩采来源另以 `resource_catalog_id` 连接资源目录。
- 正式 `scripts.run_review_agent` 在冻结会话时自动绑定手册。`2026-11-22.1` 的初始输入含卡片目录，以及当前事件触发的简短问题。完整经验、反例和来源通过 MCP `get_reference` 读取，例如 `knowledge:K04`。
- 24张卡中，20张只供查询。K10 在附近队友阵亡时提醒重新评估原目标。K01、K15、K23 同时提供可查询的经验与事件提示，分别对应本人击杀、影响当下行动的信号、新出现的敌人影响附近队友。每个提示随附本帧证据，Agent 可跳过，也可提出手册没有覆盖的机会。玩家只看到与行动有关的建议和理由。
- Agent 自选值得展开的问题。本人当下的证据已能支持建议时可以直接回答；需要具体打法或反例时，通过 `get_reference` 查卡。`review_personal_action`、`review_round_plan` 和时间、视野、机制工具用于核对局内条件。
- 新会话答卷中的 `follow_through` 绑定首选，记录继续当前动作的后果，以及每步的条件预期、复查时机、确认后的动作和未确认时的备选。新知识引用必须有本次成功读取记录。
- 下一帧继承这段计划，旧事实转为历史引用。Agent 重新确认上一条件是否成立，不自动推进。玩家卡展示简短后续；安静对线帧仍只处理本人相关事项。

旧冻结答卷继续使用旧契约。新手册不会改写旧帧，知识正文在每次运行内按内容哈希固定。程序能验证引用、步骤连接、事实时间和结构；文字是否准确理解线形，仍须战术评阅。

例如潘森和女警对大嘴、塔姆。大嘴让出了补刀位置，潘森可以提出继续站位施压，把 W 留在手里；如果大嘴补刀的位置给了先手机会，再结合女警能否跟上、塔姆能否反制来评估出手。两种走法都能成立。哪些机会在这一秒真实存在，要回到玩家当时所见。若只能看清眼前换血，就在这一步收束；等看到兵线交接、女警处境或敌方露头，再决定是否离线。这是写法示例，不作为该局某一秒的观测。

## 怎样运行与补充

现有[正式运行命令](../../README.md#复跑个人行动与赛后执行核对)无需新增参数。`--backend probe` 只探测工具，`--backend file` 或已配置的模型后端才会生成建议。新知识卡可用如下测试离线检查。

```powershell
.venv/Scripts/python.exe -m pytest tests/test_coaching_knowledge.py -q
```

新增经验时先打开原始正文或可核选段，在专题登记读到了什么、日期、版本边界和拒绝采用的说法，再更新 JSON 来源、卡片及 `version`。仅有标题或搜索摘要的资料不进入推理卡。相互冲突的经验保留不同成立条件；涉及精确伤害、距离、冷却和兵线时间时仍由版本资料及工具负责。

当前缺口仍是双方兵线交战／增援／进塔的通用数值预测，以及跨对局的独立战术评阅。手册已经能组织条件推演，不能替代这些缺口。无需为了使用手册重新补录。实际检查范围见[首版接入报告](../../reports/知识手册接入_20261119.md)与[中文社区扩采报告](../../reports/中文社区资源扩采_20261119.md)。
