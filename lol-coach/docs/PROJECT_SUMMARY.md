## 项目目标与已确定的方向

项目希望回答玩家在具体时刻面临的实际选择，例如继续发育、支援、反蹲、护推、保护回城或交换地图资源。最终输出需要解释候选行动的收益、风险、机会成本、执行条件、预计耗时、完成后的状态，以及何时应改变计划。

这一目标要求先建立四类可核验基础：地图空间与路线、英雄和装备机制、动作耗时与结束状态、真人经验。英雄判断必须结合队友和对手，不能凭单个英雄的标签直接推荐打法。模型负责组织和比较信息；缺失的机制、隐藏敌人位置或不确定的耗时，不能由模型记忆补成事实。

当前继续采用 Python 包与命令行工具，不做前端、微调或实时覆盖层。验收按已经批准的能力范围进行，已有移动成果不再因追求额外精度而反复要求补录。完整基础验收见 [基础阶段范围与验收标准](FOUNDATION_ACCEPTANCE.md)。

## 当前系统由哪些部分组成

系统已形成四个实际工作层次：

1. **资料与缓存。** 获取公开静态资料，记录来源、版本、抓取证据和内容哈希；已有缓存可供离线重建。
2. **回放解析。** 对已有回放分包，使用冻结的字段布局和字节映射导出事件与状态；研究候选与正式解析结果分开。
3. **信息过滤。** 按游戏时刻截断数据，按观察队伍和本人权限过滤，保留采样时间、历史观察和未知项。
4. **分析输入。** 输出 `macro-snapshot/v1`，组织阵容、可见状态、近期事件和证据；新增 foundation 关联本局静态技能、适配阵容的条件规则和历史经验。行动耗时目前仅支持条件算术与既有片段观察，仍不能作普遍 ETA。

项目主体位于 `lol-coach/`。主要代码在 `lol_coach/`，运行与研究入口在 `scripts/`，测试在 `tests/`，任务要求在 `docs/`，执行结果在 `reports/`。仓库根目录保留分包器、移动解码器与冻结字节映射，维持原有依赖及哈希校验。
