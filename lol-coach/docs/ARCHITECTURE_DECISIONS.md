# 架构决策记录与调研路线

2026-11-11 根据项目目标讨论、回放逆向实验、工程接管聊天和已提交工件回溯整理。以下“已采用”指已有设计和实现证据。后续的模型工具接入单独标为提案。

## ADR-01 · 按构建版本验证回放字段（已采用）

**问题与调研。** 用户最初要求只凭一份 ROFL 解释一名英雄约 30 秒的行动。击杀和赛后汇总能定位结果，无法解释途中下过哪些移动指令。用户后来提供简化自定义对局与动作时段，让分路、连续移动、停步等解释可以相互核对。[回放来源与工具](SOURCES.md) · [对照实验设计](CONTROLLED_REPLAY_EXPERIMENTS.md)

**决定与代价。** 保留原始回放及构建标识，先验证容器和数据包，再用已知动作与画面对照字段，区分计划路径和人物实际到达。相比将旧版字段表直接套入新版，这需要逐版本验证，也能隔离看似解析成功的错误。例如 16.21 的候选移动解码出现越界路径点时，系统继续保留原包并将移动语义列为未知。后续出现与该构建匹配的动作真值时再复核。[新版对照结果](OFFLINE_FINISH_RESULTS.md) · [移动验证](../reports/movement_video_validation.md)

## ADR-02 · 按时刻与阵营生成模型输入（已采用）

**问题与调研。** 复盘要解释玩家当时为何值得推线、补给或支援。整局日志便于赛后核查，却同时包含后续结果和敌方隐藏状态。把全量记录交给模型自行甄别，会让输入本身泄露答案。[项目需求](PROJECT_BRIEF.md) · [模型框架](回合复盘方案_v0.1/REASONING_FRAMEWORK.md)

**决定与检验。** 程序先冻结对局、时刻及观察队伍，区分当前观测、最后可见、估计和未知。资料按需查询，模型只在这个范围内比较行动。代价是部分局势只能给条件判断。检验方法是改变未来或隐藏数据，观察当前模型输入是否保持一致；还可检查下一张卡是否错误地把旧建议写成玩家已经执行的动作。[决策帧测试](../tests/test_reasoning_frame.py) · [前后卡测试](../tests/test_round_chain.py)

## ADR-03 · 程序核对事实，通用模型比较行动（已采用）

**问题与调研。** 用户要求先建立可核验的地图、英雄机制、行动耗时和真人经验，并强调同一英雄的打法要结合双方阵容。比较过直接拿截图让模型回答、先训练专用模型、由程序提供证据再让通用模型推理三种路线。[最初约定](PROJECT_BRIEF.md) · [国服经验调研](回合复盘方案_v0.1/CN_REVIEW_FINDINGS.md)

**决定与代价。** 程序处理版本、局内事实与引用，模型说明候选行动、机会成本、需要的队友配合以及改变计划的条件。当前文件会话需要宿主提供回答。结构检查能发现无效引用，建议是否能执行仍需复核。300 秒样例的退路曾比首选更依赖队友，实际修订保留在结果报告。只有具备可使用的标注、按整局隔离的评测和稳定基线后，才重新讨论微调。[会话运行方式](../README.md) · [案例与反例](OFFLINE_FINISH_RESULTS.md) · [训练准入条件](DEVELOPMENT_GUIDE.md)

## ADR-04 · 由宿主控制时钟并通过本地 MCP 提供工具（提案）

11 月的接管聊天中，用户提出自建 Agent 加 MCP，并要求给出技术方案。拟保留当前 Python 直接调用和文件回调作为基线，再让一个本地工具服务按当前决策帧提供兵线、英雄资料和行动比较。这样可以复用现有实现并替换模型，代价是多一层工具调用，还需要明确跨时刻、跨阵营查询的权限。公开基线已经验证文件会话和前后卡，尚缺 MCP 服务独立端到端运行证据。[现有接口与能力](PROJECT_SUMMARY.md) · [前后卡链路](ROUND_CHAIN_RESULTS.md)

**研究顺序。** 用同一冻结帧比较直接调用与 MCP 查询结果，并测试跨时刻、跨队伍查询；通过后重做相同的 300 秒及 320 秒案例，核对引用、退路和前卡承接；最后再由独立评阅人比较两种输出并记录调用量与延迟。同时，对新版施法、背包、区域视野等字段按对照实验逐项补证。只有依赖对应字段的结论等待补证。[验收指南](DEVELOPMENT_GUIDE.md) · [实验操作单](CURRENT_STAGE_EXPERIMENTS_20261101.txt)
