# 后续推进与验收指南

更新：2026-11-01。本文件只保存当前执行规则与依赖；当前成果见[能力现状](PROJECT_SUMMARY.md)，正在处理的任务见[CURRENT_TASK](CURRENT_TASK.md)，运行命令统一放在[项目README](../README.md)。历次排期与已交付切片规格见[整理前快照](history/DEVELOPMENT_GUIDE_before_20261101.md)，不再由旧“下一项”驱动重复工作。

## 处理链路

| 层 | 入口 | 必须保持的边界 |
| --- | --- | --- |
| 原包与版本 | 根分包器/移动decoder；replay_container；各export脚本 | 构建单独验证，容器可读不等于游戏语义正确 |
| 可知局势 | macro_snapshot、analysis_context、lane_wave | 只用截止时刻可知的观测；隐藏、未来、来源不符的值不进入事实 |
| 决策输入 | reasoning_frame、lineup_references | 当前事实、历史、估计、静态资料和未知分开；资料按需查询 |
| 检查点 | round_boundaries、review_checkpoints、build_review_sequence | 调度策略不冒充真实回合；合并时不丢变化、不回填未来；未选帧不自动当负例 |
| 回答与承接 | reasoning_runner、decision_contract、round_chain | 旧建议不当执行证据；同源同视角和前后时刻绑定；无有效前卡可独立分析 |
| 评测 | boundary_dataset、review_evaluation | 同局隔离；先冻结输入再评阅；独立标签缺失就留空，不用胜负或模型自评替代 |

字节解析、字段语义、当时可知、模型接入和战术效果是五层检查，不能互相代验。

## 后续工作按依赖分开

| 分支 | 输入与输出 | GWT和停止条件 |
| --- | --- | --- |
| 新版适配与未解字段 | 已有消息族/窗口＋新的可区分约束→候选规则、反例、保留检查 | Given两个竞争解释，When对照新约束，Then只接受被独立证据区分的规则；无法区分保留未知，不反复运行同一猜测 |
| 时间准入 | 冻结预测＋独立起止区间→误差/未到反例及适用范围 | 继续遵守[ACTION_TIME_TEST_TASK](ACTION_TIME_TEST_TASK.md)的T5/T6；软件失效处理通过不代替实局精度，不把门槛机械改成用户需录20段 |
| 检查点/战术评价 | 现有选中与未选时刻＋独立标签→错误分类与调度/推理改进 | Given隐藏后验结果的输入，When评阅，Then不按胜负倒推；未看答案的保留集与开发反馈分开；无标签不报质量通过 |
| 资料覆盖 | 实际阵容及明确缺失机制→带版本、条件、反例的资料条目 | 来源入口/自动摘要不当完整阅读；机制未触及本局时不硬套；缺局内可用状态仍保留条件 |

这些分支可以使用已有充分证据独立推进。录像只阻断依赖对应真值的结论，不能成为所有开发的总开关。完整采集安排只维护[实验操作单](CURRENT_STAGE_EXPERIMENTS_20261101.txt)；[原对照设计](CONTROLLED_REPLAY_EXPERIMENTS.md)解释竞争假设，不另开一份不同的录制清单。

## 模型与训练

当前一个通用分析模型配工具即可：程序负责版本、事实、时间/权限边界、计算与引用检查，模型负责双方职责、行动比较、机会成本和退出条件。资料中的命令只作不可信数据，不执行。

先冻结当时推荐，再单独分析后续结果；不能把后果倒填进决策输入。数值ETA/精确冷却/区域视野未过对应准入时，输出条件与未知，不说“肯定来得及”。

先按错误原因改数据、检索或提示/契约；只有来源可使用、标签经过复核、整局隔离数据、固定通用模型基线和持续目标错误均具备时才评估训练。SFT/DPO属于后续可能方案，没有被本轮授权为当前任务。原研究方案中的局数、质量百分比与训练样本数仍是草案，不由本次文档整理自动批准。

## 每轮最小交付

1. 在任务卡写任务ID、输入输出、允许改动、GWT、检查命令、停止条件和恢复点；复用现有规范。
2. 用新文件/目录保存输出和失败，保留原件；不得因为回放不可重开就猜标签。
3. 执行风险对应检查；相关测试通过后不无故扩大或重复。修改源码或发现新反例才补必要验证。
4. 报告PASS/FAIL/INSUFFICIENT_EVIDENCE，NOT_APPLICABLE须有依据；绑定版本、证据和执行主体。人工签署未提供就空置，费用/Token未知不填0。
5. 更新CURRENT_TASK、能力总结及STATUS。能力总表不逐轮追加历史段落；历史结果留专门报告或history归档。
