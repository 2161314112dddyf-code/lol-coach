# 后续推进指南

更新：2026-10-28。用途：让接手者知道下一步改哪里、交付什么、怎样判断做完；当前结果以[状态记录](../reports/STATUS.md)为准。本文落实[项目宪法](PROJECT_CONSTITUTION.md)和[工作约定](WORKFLOW.md)，不修改宪法、不补签人工验收，也不把下文待实施任务写成已有能力。

## 目标与当前落点

做赛后决策复盘：还原玩家在时刻t能知道的局势，结合双方阵容、可核验机制、空间与动作成本，比较行动并解释退出条件。按玩家的行动目的和约束变化组织回合；不同队友的回合可以不同步，不能固定每隔若干秒硬切。

已经跑通单决策点的资料查询、模型作答、检查和中文卡片。2026-10-26完整回归为599项；三个真实冻结时刻首轮2/3完成，一次文件响应超时后恢复为3/3结构与引用通过。它们来自同一局的连续片段，不是独立国服盲测，也不是战术准确率。[真实试跑](回合复盘方案_v0.1/REAL_REPLAY_RESULTS.md)与[14题模拟迭代](回合复盘方案_v0.1/SIMULATION_RESULTS.md)保留不同证据口径。

继续使用Python与CLI，不先做前端或微调。缺少资料只能限制依赖它的结论；不靠模型记忆补数据，也不以补录更多移动录像作为推进前提。

## 源码与数据从哪里进入

以下路径相对`lol-coach/`；仓库父目录的冻结分包器和字节映射仍是依赖，不能只复制子目录。

| 层 | 已有入口 | 接手时要保留的边界 |
| --- | --- | --- |
| 已接受回放导出 | `scripts/run_replay_completion.py`；`export_lane_identities.py`、`export_neutral_identities.py`等 | 原始回放及导出留本地；脚本绑定研究版本和现有素材，不是任意回放通用解析器 |
| 玩家可知视图 | `lol_coach/macro_snapshot.py`、`analysis_context.py`；`scripts/analysis.py context` | 截止时间、观察队伍、本人权限、最后可见和证据来源 |
| 模型输入 | `lol_coach/reasoning_frame.py`；`scripts/reasoning.py prepare` | `decision-frame/v1`，事实账本及未知；审计文件与完整回放哈希不入提示 |

同一字段必须分别回答：**字节能否解析 → 语义是否成立 → 当时是否可知 → 是否已进入决策帧**。前一层通过不自动推出后一层通过。

例如，[RPL-008](../reports/replay_completion_progress.md)对现有四回放的548个兵线实体分类、26个野怪归入12组营地给出限定PASS；连续兵线位置、存活、推进方向、当前营地剩余量仍不是随之完成。实际施法/冷却、完整连续背包、区域视野仍有未解语义，不能全部改称“只是未接入”。

## 下一切片：ROUND-006-JOIN，接入有依据的兵线信息

**目标：**让决策帧明确知道哪些单位/兵线信息已经可用，哪些只是事后身份依据，减少“完全没有兵线输入”而不引入全知信息。依赖ROUND-005-REAL；这是紧接着可执行的工程任务，尚未实现。

**输入：**现有`*-lane-identities.json`、world对象导出、当前快照与原证据。先用已冻结的283/293/300秒回归输入；若这些时刻没有可用兵线事实，如实保留空结果，并从已有素材选取有证据的时刻验证正向路径，不让用户补录来凑样本。

**关键事实：**`export_lane_identities.py`目前明确输出`decision_input_eligible=False`。超级兵分类可能依赖晚于出生的`classification_available_at`；team/lane标签是交叉推导，`runtime_map_id`仍未知。因此不能把整个导出塞进模型，也不能仅把总开关翻成true。

**实现顺序与输出：**

1. 列出逐字段映射：实体、类型、队伍/路线依据、发生时间、证据可用时间、可见主体、推导等级及原证据定位。把出生记录、关键帧同步、后续见证分开。
2. 增加一个薄适配模块，由`analysis_context.py`调用；先证明字段在t可用且对观察方可知，再进入快照与`reasoning_frame.py`白名单。无可知性证据的记录留审计侧，输出明确缺口。
3. 只呈现已被支持的历史或当前事实。出生数不等于存活数，出生坐标不等于当前位置，营地归组不等于营地已刷新；不凭这些输入宣称可以安全推塔。
4. 生成更新前后同一决策点的字段差异、中文卡与验收记录。语义输入相同不强求模型推荐变化；变化必须能说明由哪条新信息支持。

**允许改动：**新适配模块、`analysis_context.py`、`reasoning_frame.py`、相关CLI加载和必要测试、状态/报告。冻结解码规则及原始资料只读；若发现解码反例，另记Finding，不在此切片顺便重写全部解码器。

| 验收ID | Given / When | Then |
| --- | --- | --- |
| L1 来源与时间 | 给定同一回放的正常、未来见证及错来源记录，编译t时刻 | 合法字段有单位/时间/证据；未来见证不升级早期分类，来源或构建不符明确拒绝 |
| L2 可知边界 | 固定截至t可知记录，只修改之后或观察方未知的对象状态 | 模型语义输入不变；完整文件哈希变化只留审计，不能泄漏到模型 |
| L3 不越级推断 | 只给出生、身份或旧位置，再构建兵线视图 | 不生成当前存活数量、当前站位、压线方向或可推塔结论；缺口可定位 |
| L4 缺失兼容 | 缺导出或没有合格可知记录，运行原单帧链路 | 原可用事实与条件建议仍可产出；不能静默补零或把缺失当失败整局 |
| L5 实际交付 | 对已有真实材料运行适配、离线负例与回归 | 保留输入版本、实际输出、拒绝原因和命令；分别统计接入成功与证据不足，不用测试数量代替实况覆盖 |

**完成/停止：**上述接口与检查完成即交付，不为增加分类精度无限补测。若没有任何字段通过可知性判定，不能宣布“兵线已经接入”；交付拒绝清单、有限缺口及已完成的适配/负例检查，继续不依赖这些字段的ROUND-007。只有确需用户决定的素材授权、外部费用或实验操作才交人处理，并说明具体阻断哪项验收。

## 模型怎么用，什么时候考虑训练

目前一个通用分析模型配工具即可。程序负责事实、权限、时间、计算和契约；模型负责双方职责、候选比较、机会成本、退出条件与简短理由。模型看不到未来结果时先冻结推荐，之后的结果解释单独运行，不能反改原推荐迎合输赢。

错误按原因处理：状态缺失/错时先修数据；找不到资料先改检索；遗漏队友条件先改提示与契约；信息充分但持续不会比较行动，才评估训练。不能用微调替代尚未搞清的游戏机制或回放字段。

训练启动前要同时具备可使用来源、经复核标签、按整局去重隔离的数据集、固定通用模型基线，以及反复出现的目标错误。先做小规模SFT对照；偏好标签稳定且问题确在行动排序时再考虑DPO。保留通用模型回退；只改善措辞、开发题或泄漏测试答案不算有效提升。具体模型、费用和训练预算另行依据实测与用户授权决定。

[原方案](回合复盘方案_v0.1/ROUND_PIPELINE_SPEC_V0_1.md)中的10局/50回合、质量百分比、P95、训练样本数都是**待批准的规模或门槛草案**，不是本指南新批准的验收。正式盲评前固定范围与门槛，不能用599个代码测试或3张条件卡抵扣战术验收。

## 每个任务怎样交付与接管

开始时在[CURRENT_TASK](CURRENT_TASK.md)写任务ID、输入输出、GWT、允许改动、恢复点；按本指南的下一切片推进，避免重新写泛泛规划。修改前以提交或逐文件备份留下恢复点，输出用新目录。

在`lol-coach/`可先运行已有离线检查；临时目录名每次更换并确认不存在：

```powershell
.venv/Scripts/python.exe -m pytest -q tests/test_lane_identity.py tests/test_lane_attributes.py tests/test_macro_snapshot.py tests/test_analysis_integration.py tests/test_reasoning_frame.py --basetemp data/private/test_tmp_lane_new_run
.venv/Scripts/python.exe -m pytest -q --basetemp data/private/test_tmp_full_new_run
.venv/Scripts/python.exe scripts/reasoning.py --help
.venv/Scripts/python.exe scripts/run_reasoning_session.py --help
```

上面是可复用命令，不代表本次文档更新已执行这些测试。新行为增加对应的正向/边界/反例测试；通过当前验收后停止重复测试，除非出现新改动或反例。真实导出与模型试跑按[框架说明](回合复盘方案_v0.1/REASONING_FRAMEWORK.md)和[文件协议](../reports/real_reasoning_validation.md)执行，公开克隆没有本地私有回放与缓存，不能宣称仅克隆就能复现全部实况。

报告每项使用`PASS / FAIL / INSUFFICIENT_EVIDENCE / NOT_APPLICABLE`，绑定目标版本、证据、实际执行者和范围；NOT_APPLICABLE需要明确依据。记录失败、修复、命令和退出码，费用/Token未取得就留unknown。人工签署栏没有真人签署就留空。

完成后更新STATUS最新条目，保留历史，写清“本轮完成—仍缺—下一项—是否需用户接手”。公开GitHub发布源码、规则、测试和可读报告，原始回放、视频、客户端、缓存、私有派生数据及密钥留本地。每次同步核对提交清单、远端分支和最终提交ID；不把代码发布等同产品或战术正式验收。恢复采用逐文件比较或新修复提交，不整目录覆盖之后的工作。
