# 第一轮任务：基础数据探测与一个真实样本闭环

## 本轮交付，不是整个项目

实现一个最小命令行工具：查询候选数据源；保存证据与版本；取一份真实英雄基础数据；规范化关键字段；执行离线测试。
同时核实地图导航、机制和行动实测的入口，列出未打通项。本轮不实现完整寻路、刷野模拟、ROFL 全解析或 AI 点评。

以下模块名与命令是建议的目标接口，当前并不存在。已有项目采用等效结构即可，README 必须写实际命令。

## 1. 检查环境和目录

确认根目录、现有文件和 Git 状态；检查 Python，不覆盖用户项目。为本项目建环境并固定依赖，不擅自修改全局配置。
优先简单实现，避免微服务、向量数据库和复杂前端。

## 2. 实现资源探测与证据记录

首轮重点：官方 Data Dragon、CommunityDragon、Meraki、NGRID converter、刷野资料入口和 ROFL 仓库。
对公开 HTTP 读取设置超时、有限重试、缓存与请求间隔；区分网页可访问、数据可解析、字段已验证、版本未验证。

每个探测结果至少包含：
`source_id, requested_url, final_url, retrieved_at_utc, http_status, content_type, sha256, content_version, status, evidence_path, limitations`。

分别记录 source 的许可/服务条款线索。HTTP 200 不能自动等于可商用或当前版本兼容。
需要密钥、登录、本地文件的来源标记 `blocked` 或 `needs_local_file`；不要读取浏览器 Cookie 或尝试规避权限。
查不到目录或下载失败时保留日志，不构造虚假的数据响应。

## 3. 打通官方英雄数据样本

查询官方版本列表。让工具支持显式 `--patch` 参数；首次开发可选择列表实际包含的版本，但必须写入结果，不只保存 latest。
下载中文或英文的一份英雄详情，示例 Ivern，再按实际字段规范化：
英雄标识、数据版本、基础移速、基础攻击距离、基础生命/法力、技能原始描述、字段来源。
字段不存在保留 null 和原因，不猜测复杂技能范围或冷却。
数据版本不能自动证明目标游戏客户端版本已匹配；单独存这个校验状态。

示例目标流程（实现后必须以实际命令更新）：
`python -m lol_coach audit-sources`
`python -m lol_coach fetch-champion --patch <已确认版本> --champion Ivern`
`python -m pytest`

保存原始响应、来源 manifest 和规范化文件，方便后续核查。静态移速不是某局当前实际移速，字段名必须体现这一点。

## 4. 核实其他基础入口，不捏造完成度

- NGRID：阅读 README 和代码入口，确认需要的文件格式、输出格式、支持线索、当前缺什么资产。尚无对应版本网格，就不能计算所谓真实路线。
- 地图配置 JSON：只核验实际字段和对象，不当成导航网格；下载较大文件前检查大小与任务必要性。
- Meraki：检查具体样本的字段及版本线索，不把 latest 视为当前版本。与官方数据冲突时保留分歧，不静默覆盖。
- 刷野资料：记录可访问的作者/来源和版本证据，定义实测记录模板。没有明确许可或可读内容，不批量获取整段视频。
- ROFL：检查文档和维护状态。没有真实回放时只能说“读过项目”，不能报告“解析通过”。

## 5. 编写测试

至少包含：
- 合法英雄样本的字段映射。
- 缺失字段为未知，而非补 0。
- 原始数据没有版本证据时，结果不标成版本验证通过。
- 网络失败、错误 JSON 和非 JSON 页面不会被记作成功解析。
- 来源与原始证据路径能回溯。
- 离线测试无需真实 API 密钥或付费模型调用。

合成 fixture 明确标 `synthetic`。在线 smoke test 与离线单元测试分开，注明本次是否真实执行。

## 6. 输出报告

生成 `reports/source_audit.md` 和 `reports/STATUS.md`，说明：
真实取得的文件、可核查字段、版本、实际运行命令、测试数量、跳过项、下一项任务。
附少量真实规范化字段，或明确说明网络受阻没有得到真实样本。

## 验收

有网络时：至少一份真实官方英雄数据＋可复现规范化命令＋测试结果＋资源证据记录。
无网络时：完成工具和离线测试，在线验证标为未完成；给出恢复网络后的命令，不能宣称满足真实数据验收。

不允许以“我建议用某框架”或一张漂亮原型图代替本轮交付。
