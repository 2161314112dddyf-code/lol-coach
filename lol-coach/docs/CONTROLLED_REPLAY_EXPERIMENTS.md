# RPL-009 对照实验方案 v1

日期：2026-10-23。状态：设计完成，尚未执行或要求用户现在开游戏。依据：用户要求“设计详细实验”。目标是用能区分竞争解释的干预解决 RPL-008 剩余字段；不重做已接受的移动和现有样本兵线/营地身份验收。

## 1. 实验要回答的三个问题

1. 什么原包字段能区分未成功释放、实际释放、持续施法被中断？计时数值表示剩余时间、结束时间、总时长、速率还是缓存？
2. 背包使用消息中的槽位、数量、充能与物品状态如何对应？实时消息与关键帧各字段是否及时更新？
3. 视野源什么时候生效/失效，哪些消息只表示对象可见，哪些信息能重建地形区域可见性和遮挡？

实验成功的标准是排除错误解释并找到可复用解码关系，不是多录几场或增加测试数量。设计者预测与实际观察分别保存；这里所有预期都是待检验假设。

## 2. 先解决版本和采集可行性（E00）

现有四份回放精确构建为 16.20.824.8524，本地游戏可执行文件已经变化。不能默认今天录制的回放仍兼容旧解码器。

执行顺序：

1. 我先从现有文件提取版本、SHA256、原始事件清单和可配对片段。现有比赛中的自然对照只标为观察性证据：不能宣称已控制装备、等级、死亡和其他机制。
2. 若开展补录，先做一次短试录：固定英雄站定，不操作 10 秒，使用一次技能，再不操作 10 秒，正常结束。总时长以能正常结束并保存回放为准，不承诺训练模式一定支持 ROFL。
3. 检查是否能得到完整 ROFL、是否能提取消息边界/时间/实体，以及录像能否看清技能栏、背包、状态面板和游戏时钟。此检查通过前不录长实验。
4. 新构建不能解析时，停止批量采集；保留这份小样本供适配。新版本实验结果与 16.20 分库，不能把新版本槽位字节直接映射到旧版 `ec`。跨版本只能先迁移语义假设；字节布局/映射必须各自验证。

不要求降级客户端、绕过版本限制或启动旧回放。用户未执行新实验时，我继续现有素材的配对提取与分析。

## 3. 共用控制条件和记录方法

每组记录：精确版本、地图/模式、英雄、等级和技能等级、符文、装备及所在槽位、技能急速/召唤师技能急速/物品相关急速、生命资源、死亡状态、增益、自动刷新开关。无法看到的条件填 unknown，不填默认值。

- 使用能实际保存回放的环境；是否支持锁级、加钱、关闭刷新、重置技能等功能由 E00 实际核验，不能预先假定。
- 主实验关闭已确认存在的自动冷却/生命资源刷新。准备阶段的购买、升级、重置、传送操作与正式观察窗口分开；记录真实开关状态。
- 选择远离兵线、塔、野怪和其他英雄的安全固定位置。没有目标的实验朝同一个空方向施法，避免击中触发回血、减冷却或符文。
- 普通技能候选：无目标也能释放的直线投射技能，例如莫甘娜 Q；选定后先用 E00 确认当前版本行为与录像可辨识性。不预填技能冷却、消耗或施法前摇数值。
- 每次变化前后保留至少 5 秒干净窗口；冷却实验完整等待一次自然转好。不能假设 5 秒足够结束任意持续效果。
- 操作日志记录“按了什么”；录像记录“实际发生什么”。按键不是成功施法标签，按 S 不是取消标签。
- 同时保存 ROFL 和连续画面；优先保留原始帧率，记录实际 FPS，不强求为了实验升级录制设备。鼠标/键盘提示或口头报实验 ID 有助于定位，不能替代游戏内结果。
- 每块先做 3 次有效干预；前 2 次用于找关系，第 3 次封存作检查。若两次已经出现结构矛盾，先解释矛盾，不堆录十次。跨角色/物品的额外检查只用于检验已经明确的推广假设。

最小日志模板：`reports/templates/controlled_experiment_log.csv`。每行记实验 ID、重复号、意图时间、实际效果时间区间、唯一干预、完整条件、观察、异常和素材路径。

时间对齐：用同一次可见效果的录像帧与原包事件形成锚点，另用后续锚点检查漂移。记录游戏时钟、视频时间和原包时间三套值，不强制相等。UI 整秒倒计时属于量化观测；若没有确认显示取整规则，不把“显示 7”当精确 7.000 秒。容差来自帧间隔、游戏时钟分辨率和实际消息采样间隔，在拟合前登记；不能为了通过事后扩大。

## 4. 技能释放与冷却

### S01：未操作、成功释放、失败请求

固定英雄、技能等级、装备、位置、方向和被动状态；先确认技能自然转好且资源足够。

|步骤|具体操作|唯一干预|独立标签|
|---|---|---|---|
|A|站定 10 秒，不按技能|无操作|没有施法动作|
|B|按一次选定技能，之后不输入|一次成功释放尝试|录像确认投射物/释放动作、技能栏变化；资源变化仅辅助|
|C|在 B 后冷却尚未结束时，再按一次同技能|冷却中输入|录像检查是否真的未产生第二次释放|
|D|自然转好后，再做一次 B|重复成功释放|独立确认第二次实际释放|

资源不足实验另开 S01-M：资源确实低于技能消耗时按一次；不能在同一步同时改变冷却和资源。若没有可核验的不足资源状态就不执行此块。

比较：旧版候选 `0x2a1` 活动、`0x43e` 状态、`0x3df` 资源及该窗口所有其他消息。不预先把搜索范围锁死在旧操作码；新版本可能不同。

判别：B/D 共同出现、A/C 缺失的字段是成功释放候选。C 没有服务器回放消息也是合法结果：可能失败输入没有被记录，不能编造一个“失败施法包”。资源下降或投射物创建单独出现均不足以证明所有技能成功释放。

### S02：固定条件下区分剩余时间、结束时间与总冷却

以 S01 成功释放为起点，不移动、不攻击、不再次施法、不改变装备和等级，观察至自然转好，再等 5 秒。重复 3 次，改变的仅是本次施放的绝对游戏时间。

分析采样点：施放前、释放后首个可用观测、其后约 1/2/4 秒、转好前后；若技能比某采样点更早转好，记录该事实，不要求额外等待制造不存在的冷却。原包无对应采样时标“未发送/未观察”，不插值造包。

|候选含义|一次周期内预期|不同绝对时间的第二次施放|
|---|---|---|
|剩余秒数 R|随经过时间下降，转好附近到零/切换分支|同一释放后经过时间应相近|
|结束时刻 E|周期中基本不变|随本次释放时刻平移|
|总冷却 D|周期中基本不变|控制条件相同时基本不变|
|速率/倍率|静置阶段不变|相同条件通常不变，需 S03 区分|
|缓存值|与画面/连续事件可能不同步|更新时机与某类同步或关键帧关联|

这些是数值解码后的约束，不是对加密字节直接做减法。相同数值可能因序列化选择器不同而字节不同；字节相同只提示候选，不自动证明语义。

### S03：只改变已显示的技能急速

在相同技能等级下，设置 A 条件（记录实际急速 H0），完成自然冷却周期；设置 B 条件（只影响本次冷却判断的急速 H1），再完成周期；可恢复 A 时执行 A–B–A。

优先使用无主动、无冷却返还/充能/击杀触发的急速来源；实际商品与符文按当时版本确认。装备可能同时改变其他属性：完整记录，并限定为“装备干预支持急速假设”，不能冒称严格只改一个数值。若不能构成干净的急速干预，先完成 S02，不用有混杂的结果强定公式。

随后另开技能等级块：保持急速与装备，技能升一级，重复 S02。升级同时改变英雄等级/基础属性时登记混杂；不能与急速变化放在同一对照。

判别：哪个字段随技能等级改变、哪个随急速改变，哪个只是当前倒计时。常见公式只能作为竞争假设，必须用当版本来源与实测支持；召唤师技能急速不得与普通技能急速混用。

### S04：持续施法完成与中断

先选能由画面明确看到持续施法开始/结束的动作；回城可作通道事件的初始例子，不能用于证明普通 Q/W/E/R 的取消编码。

- A：站定发起持续施法，完整结束。
- B：相同起始条件发起，画面确认开始后约 1 秒，再移动中断。
- C：改变持续时间后再中断，检验候选字段是否随持续时间而变。

回城会改变结束位置，因此只比较开始至中断/完成附近的事件，并记录位置变化。若存在可验证的普通技能引导，再以它做保留检查。不能把即时技能释放后的移动记为“取消成功”。

S05（条件触发）：只有 S02 出现计时冻结/跳变，才对照存活静置与死亡期间的同类冷却，记录死亡、复活和任何重置；不把死亡实验列为首轮额外录制门槛。

技能验收：真实成功/未成功/中断标签能与事件对应；定时字段在保留周期中保持一致的时间含义；旧版剑圣关键帧反例必须被模型解释或明确排除为另一状态分支。不能仅凭拟合训练片段就宣称精确冷却解出。

## 5. 背包槽位、使用与缓存

### I01：身份与操作顺序基线

安全位置，固定英雄，初始七个可见槽位逐格截图。选择当前模式可买的简单基础组件。分开执行：购买一件 → 等 5 秒 → 换槽 → 等 5 秒 → 出售 → 等 5 秒。撤销在另一个独立块：购买 → 在未战斗/使用/换槽的情况下立即撤销 → 等待。

不假定撤销按钮总可用；按钮不可用标为“未完成操作”，不能算协议失败。记录金币净变化及期间收入，区分购买退款和自然获得金币。

### I02：同一个主动物品轮换槽位（最高优先）

目的：直接约束旧版 `0x3f1` 的未知槽位含义；新版本结果仅适用于新版本。

1. 选择当前模式可用、可在安全环境触发的有充能消耗品或主动装备；先试一次确认使用条件。若用药水，先保持可核验的非满生命，不能把满生命使用失败当成功。
2. 先放第 1 格，记录物品 ID、UI 格号、内部索引（若已解）、数量、充能和冷却；自然可用时使用一次。
3. 恢复使用前条件，移动同一物品到第 4 格，重复；再到第 5、6 格。
4. 一次只做“换槽”或“使用”；两操作之间留窗口。每次使用比较相同充能转换，例如都从 2→1，而不是把槽位改变与 1→0 混在一起。
5. 初次覆盖各格后，用另一种可安全使用的主动物品在候选未知格做保留检查。

同一物品、同一数量/充能变化，只换槽位，能区分槽位编码与物品编码。物品不允许移入饰品格时不强行操作；第 7 格应另用该格合法物品，不能声称这仍是同物品单变量实验。

### I03：数量、充能、使用冷却分离

固定同一格：A 不使用；B 使用一次；C 充能允许时第二次使用。分别记录物品是否仍存在、堆叠数量、剩余充能、图标倒计时。只有一个量确实变化的片段才作为该量的纯对照。

被动叠层另开块：例如已验证可买的贪婪之靴，固定购买时间和装备，比较无击杀参与与一次明确击杀/助攻。不要同时换槽、升级或买其他装备。操作成本过高时优先复用现有烬 3/9 层独立事件核对，不要求重新录。

### I04：实时事件与关键帧的字段时间

先由 ROFL 读取器识别该版本真实关键帧时刻，不能默认每分钟。安排一次操作后保持状态不变，使后续至少一个关键帧覆盖它；不要同时执行两次相反操作造成无法区分。

比较四条独立时间线：录像中的背包状态、操作事件链、实时全列表、关键帧/复合缓存。若某字段滞后，记录其首次更新时刻和触发消息。分别检验 ID、堆叠、充能、成长属性和冷却，不能由 ID 一致推断其他字段都及时。

背包验收：保留操作序列能恢复七个可见槽位身份/数量，并分辨充能与物品冷却；未知输入不清空槽位；明确哪些字段是观测、可持续保持或必须标未知。`ec` 只有在同构建且存在直接约束时才贴具体槽位标签，不能仅凭物品用途猜。

## 6. 视野：来源、对象与区域分别实验

可靠的主动干预通常需要两个可控阵营：A 为观察队，B 为普通、非隐身目标英雄。是否有可用双人环境和回放能力由 E00 核验。方案不要求现在邀请他人，也不授权自动操作或联系他人。

只有单人素材时，先用已有出生/终止和可见性事件作观察性分析；若回放观察阵营模式能确认只显示指定队伍真实视野，可作辅助，否则全知观战画面不能作 A 队视野真值。

共同布置：目标区远离 A 队塔、兵线、其他英雄、宠物和其他眼。A 英雄放眼后必须离开到不再贡献目标区视野的位置；等待放置者自身视野的干扰消退，并验证。B 不攻击、不施法、不回城，无隐身/伪装；其输入、位置及状态另记。不要把敌方单位消失直接解释为整片地形不可见。

### V01：固定目标，只改变一个视野来源

1. 无眼，B 固定位置，记录 A 队地形迷雾及是否看到 B。
2. 放置一个普通视野来源，A 英雄撤离；其余条件不变，记录 A 队是否看到 B。
3. 等同一来源自然失效，B 仍不动；记录来源对象、地形迷雾、B 可见性各自变化的时间。
4. 第二块改为主动摧毁来源，其他条件一致。攻击者的暴露/攻击效果可能干扰；将这些与来源失效分开记录，不与自然到期混为同一对照。

比较 `0x1f3` 创建、`0x490` 终止候选、`0x484/0x3cd` 对象可见性以及窗口内其他消息。操作码仅为 16.20 线索。明确检验“终止时刻=视野关停”“零血量=关停”“存在延迟”三个竞争解释，不能预先选一个。

### V02：开阔地边界与方向

固定来源位置、来源类型和等级，A 英雄仍远离。B 在无草/墙干扰的方向上分步移动，每个停点站定至少 2 秒；观察到可见性改变后，回到上一个点，再缩小区间。

先测一条往返线，再选另一方向。记录来源和 B 的可靠位置观测；没有可靠世界坐标就只报告地图标记区间，不输出精确半径。进入和离开可能有延迟/滞回，分别统计，不只拟合一个圆。

### V03：草丛与墙体，分成两块

- 草丛块：来源固定，目标以邻近的草外/草内停点交替，尽量匹配距离。草丛边界与目标碰撞体可能影响结果，完整保留位置误差。
- 墙体块：来源固定，选择距来源近似相等的无遮挡点与隔墙点；不让测点同时跨草丛。再做来源—目标方向交换作为保留检查。

这些是匹配空间对照，不能假装位置完全相同、只有墙体变化。只有结合地形数据和多个相匹配点，才可能识别遮挡规则；不预设所有墙都必然阻断或任何草丛都相同。

### V04：两个来源重叠

先分别确认来源 A、来源 B 单独都能覆盖同一个固定目标点。随后两者同时存在，移除 A，再移除 B。若 A 消失就让区域变黑，而 B 仍有效，说明候选实现错误地把单个对象寿命当成全队视野。

首轮只用普通视野与普通目标；真视、隐身和特殊技能揭示另列扩展，不能用未做的实验声称支持这些机制。

区域验收：既要有对象可见性事件，也要有视野来源作用与失效、地形遮挡的依据。用未参与拟合的位置/方向/重叠状态检查预测。少量点实验只能验证这些位置；要称“区域视野重建”，仍需找到可覆盖网格的协议状态或有依据的计算规则，不能把几个点外推为全图已解。若回放不传区域网格，应明确评估是否能用来源状态和地形重建，而不是无限搜索一个未经证明存在的 fog 包。

## 7. 原包分析流程与停止规则

1. 为每个素材保留原件哈希、构建和完整顺序。提取所有操作码，不只提取已有候选。
2. 按实体、流、消息族、相对事件时间和字段结构对齐。先解析选择器/可变长度字段，再比较值；不得把两个完整 ROFL 做逐字节 diff 当成实验结论。
3. 先比较 A 与 A 重复组，找出随机编码、包序号、时间戳和自然刷新造成的变化；再比较干预组。只在控制组稳定的候选上讨论变量关联。
