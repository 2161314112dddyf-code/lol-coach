## 一、复用什么，新增什么

沿用现有解析器、证据ID、版本化基础资料、`macro-snapshot/v1`、`scripts/analysis.py context|timeline|travel`。新增薄层负责回合组织与模型分析，不迁移既有模块。解码覆盖按字段声明传递；不因某个字段未知停掉整局报告，也不回写旧报告为“全部已解”。

拟定处理边界：

| 输入/步骤 | 处理责任 | 输出/约束 |
| --- | --- | --- |
| ROFL和玩家选择 | 既有解析＋程序 | replay ID、SHA、构建版本、地图/模式依据；不支持的部分明确报出 |
| 事件状态账本 | 程序 | 事件发生时间、观测时间、可用时间、实体、单位、来源、状态有效期 |
| 决策视图 | 程序 | 只含截至t可用信息；最后看到的位置与当前可见位置分列 |
| 基础查询 | 程序＋资料库 | 路线/耗时区间、结束状态、版本机制、双方交互、资料适用条件 |
| 候选边界 | 规则先行 | 回补、兵线/营地、目标、状态变化等候选；记录触发证据 |
| 回合解释 | 通用模型 | 为候选分组，标注目的、关键节点与改计划原因 |
| 行动比较 | 同一分析模型 | 2—3个选项，包含实际动作；若实际动作尚未发生，先不开放 |
| 检查和渲染 | 程序为主 | 结构与证据检查；不合法答案最多修订一次，仍失败就显示受限结果 |
| 后续解释 | 分离的后验步骤 | 加入实际后果；不可改写先前冻结的推荐来迎合结果 |

所有步骤缓存键包含输入哈希、工具/规则/提示词版本与模型版本。缓存原始结构化回答、工具输入输出和错误；同一运行可恢复，不把“重跑措辞一致”当战术正确。

## 二、怎样划回合而不变成流水账

**同一玩家主时间线连续覆盖整局**：准备、发育、进攻、守势、转场、被迫等待均有归属；没有精彩事件的段落可折叠。其他玩家各有自己的时间线，团队机会窗口跨这些时间线关联。

程序从事件变化提候选，不按固定秒数强切。候选只有在“可选行动、行动目的或重要限制改变”时才成为关键节点；一个普通伤害包不会单独形成回合。模型合并重复节点，但每个边界必须能解释。

标注者给开始/结束的**合理时间区间和触发事件**，避免争论唯一一帧。窗口出现但玩家没有行动，也应记录为一个待分析机会，不能只围绕后来产生击杀的片段取样。

回合结束可以在赛后确定，分析t时不能提前知道真实结束时刻。结果导向选出的片段允许用于教学展示，但盲测还必须包含没有击杀、没有目标收益的正常段落。

## 三、最小分析契约

```text
round
  identity: replay_id / patch / map_mode / observer / player / round_id
  boundaries: start_interval / end_interval / trigger_evidence / parent_phase
  decision_points[]
    at / known_snapshot_ref / verified_history_refs
    objective / why_now / relevant_allies_and_opponents
    constraints: resources / wave_camps / mechanics / vision / timing
    window: expiry_conditions / time_range_or_unknown / evidence_refs
    alternatives[]
      action / route / preconditions / ally_followup / enemy_responses
      duration_range / end_state / gains / costs / risks / abort_signals
      evidence_refs / assumptions / unsupported_dependencies
    recommendation: preferred / fallback / switch_conditions / conclusion_level
  retrospective: actual_actions / observed_outcome / decision_vs_execution
  lesson: next_game_rule / counterexample / evidence_refs
```

所有数值携带单位、时间和来源；事实、工具估计、经验判断、未知分别标记。`conclusion_level`区分“支持推荐 / 有条件推荐 / 无法排序”，不凭模型自信给出胜率。原始模型推理不作为事实证据，保留可检查的简短理由即可。

队伍共享可知信息与玩家实际注意到的信息分开：没有第一视角或玩家陈述，最多说“当时可以获得这条信息”，不能指责其明知不看。

国服补充：`identity`分别记录地区、原大区、匹配池、实际队列与来源；`ally_followup`区分能离线、能到达、能有效参战及已经观察到的响应。回合内保留各人不同的兵线/补给时间表，检查金币是否已转成可用装备。某字段未知只限制相关建议，不自动要求用户补录。

## 四、模型如何形成判断

每个决策点先建立事实摘要，再检索同地图/版本兼容、相似阵容关系与资源条件的资料，最后比较选择。检索同时找适用例和反例；英雄标签不能替代对本局队友跟进和对手反制的检查。保留历史有效事实的索引，不能只靠一段可能失真的聊天摘要。

行动时间由工具提供：路线、移速变化、实施耗时、完成后生命/资源、队友到达和对手可能介入区间。行动消耗的预算包含**移动＋执行＋必要的退出/重新站位**。机会截止由兵线进塔、对手回补/到场、关键状态消失等约束决定；它们是当时预测，不是未来实况。

只有耗时上界仍小于窗口下界，才可给出“时间上有余量”的强结论；区间重叠就给条件判断。没有完整数值时，仍可比较“先做会过期的事”与“可延后的事”，但不能编造赶路秒数、成功率或收益差。机会成本要包括被放弃的兵线、营地、地图另一侧和下一回合，而不止本次金币。

首版用一个强推理模型；较便宜模型只在对照证明质量等价后承担检索整理或报告压缩。选择两种候选通用模型，与“规则＋模板”基线在相同输入和工具上比较。固定版本、解码参数和调用记录。另一模型自评只能发现问题，不能替代人工战术验收。

## 五、有限且可执行的验收

首批范围建议：召唤师峡谷、打野个人视角、选定兼容版本；必须读取双方阵容与三路线况。当前完整本地样本为单线地图，短峡谷回放不足整局，因此**本轮场景不是这套峡谷盲测的通过证据**。训练和评测用局可在下一实现阶段通过已有授权材料/公开可用记录补足，不要求用户现在开游戏。

冻结10局、50个独立人工参考回合。刷野/抓人、兵线/转线、资源争夺、撤退/回补四类各不少于10个；每个回合指定一个主类别计算分母，其余可交叉标记。包含优势、劣势、无事发生和缺字段样本。人工先只看决策前信息标注，再开放结果。调试样本与盲测整局分离。

50个回合所在的评测区间及两侧背景一并冻结，区间内所有真实边界都要标注。R3只统计这些完整标注区间内的输出，不把整局其他未标注段落算作误报；另外保留正常长发育段，检查过度切分。完整报告覆盖整局，但战术质量只在这50个预定回合上计分，不能由模型自选容易的片段。

| ID | Given / When | Then：通过标准与证据 |
| --- | --- | --- |
| R1 可知边界 | 固定t以前全部可知数据，只改未来或隐藏数据，再构建决策输入 | 决策语义输入逐字段不变；任何泄漏即FAIL。整文件SHA、运行时间等审计元数据旁路保存，不送入模型；不要求随机模型措辞不变 |
| R2 事实约束 | 输出具体事实/耗时/机制，执行引用检查及人工核对 | 引用覆盖100%；引用内容支持该断言。关键错版本、无依据状态、非法动作0例 |
| R3 回合切分 | 冻结参考边界区间与触发事件，匹配自动回合 | 触发相符且起止落入合理区间才一对一匹配；召回≥45/50，精确率≥90%。一个超长段不得抵多个回合 |
| R4 行动质量 | 人工盲评全部50个参考回合对应的回答 | ≥40/50合格；缺输出/全程拒答计不合格。专家认可合理行动集合，不强求唯一动作 |
| R5 异常与退让 | 旧地图规则、过期位置、缺CD、延迟队友到达、未来击杀提示等故意缺陷样本 | 每个缺陷都被拒绝或降为明确条件；程序正常退出不等于建议正确 |
| R6 交付与开销 | 固定机器、10局、固定模型配置跑端到端 | 每局都有报告或显式错误清单；没有静默失败。暂定P95≤10分钟；逐局记录调用/重试/费用，未获读数写unknown |

R4单卡合格同时满足：目的正确、相关双方关系讲清、至少比较两项候选、时间和机会成本有依据或有边界、推荐及改计划信号明确；并且R1/R2无硬伤。允许凭证据排除不可行候选，不强迫编造第二个可行动作。确实不足以排序时，说明缺哪条决定性信息、给出相应分支也可合格；无差别模板拒答不能过关。多个答案均合理可并列。仅文风不好与游戏判断错误分别计数。

由用户或其认可的评阅者评50卡；建议其中20卡再由另一位合格评阅者交叉核对。有分歧就记争议、协商参考答案，不把“主播这样做过”当唯一标准。当前无人签署，也未聘请评阅者。模型更换可增加配对盲评，不能反复挑喜欢的样本。

50个回合是首版阶段验收，不能外推所有英雄/版本。验收门槛签署后固定；只有已发现反例影响某条门槛时才修订，不继续追加无关补录。

## 六、训练数据与训练启动条件

一条训练记录含：局/版本/来源与使用权限、截至t局势、双方机制资料、回合边界、候选行动、人工认可的行动集合、依据、退出条件；后验结果单独存。主播实际操作、主播口述建议和我们补写的分析分列，不能互相冒充。无法确认当时可知条件的视频仅做经验卡。

先标100个开发回合，统一标签和错误分类。之后如确有训练需求，再试1,000—3,000条复核样本、覆盖至少100局；这些是预算起点，不是数量保证。来源应有多个讲解者并保留反例，公开可读不自动视为允许整段用于训练。

按整局分组划分训练/开发/测试，同一局的不同片段不得跨组；再单列新玩家、未见阵容和较新补丁的迁移集。去除重复转载及改写近重复。冻结的50个验收回合不进入检索案例库、提示词示例或训练集。

训练顺序由错误决定：

1. 找不到适用资料：先改检索/排序；切分乱：先调规则，必要时训练边界分类器。
2. 事实与工具齐全，仍稳定漏掉机会成本、队友条件或退出条件：才试SFT，让模型学习输入到合格回合卡的映射。
3. 已能稳定产出合格卡，但排序不符合可靠专家偏好：再试DPO；标签必须说明偏好源于战术还是表达。技术来源为[DPO原论文](https://arxiv.org/abs/2305.18290)，其结果不证明LOL策略正确。

保留通用模型基线。训练版必须在冻结集提升R4、保持R1/R2/R5，并在独立扩展集复现；若只改善语气或训练样本，退回基线。未观测的反事实行动不标成确定胜负，不把主播赢局直接当好策略标签。

不在本轮指定购买GPU或付费训练。先用20个开发回合实测输入/输出Token、耗时与人工标注分钟数，再算“每局调用费＋标注工时＋训练试验费”。本地权重模型与参数高效微调仅作为后续可选实现，硬件按选定模型、上下文长度和预算再确定。
