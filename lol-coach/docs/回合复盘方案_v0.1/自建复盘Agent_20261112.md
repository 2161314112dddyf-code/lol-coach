# 自建复盘 Agent 应该怎样判断一回合

逐回合宿主现已实现。可从[实际运行方法](../../README.md)打开工具证据或让模型生成卡片。十人局的红蓝视角、时窗与前卡重评见[实现后的自验记录](../../reports/round_agent_acceptance_20261112.md)。

后续扩样补充了三类原片对照，涉及一个人多留几秒能改变什么、队友能否同时输出并躲开群控、以及现在交技能会损失哪一回合。实施时间计算前，先看[扩样结果与验收例](教练复盘扩样_20261112.md)。

2026-11-12 · AGENT-STUDY-01。玩家看完一张卡，应当知道**现在做什么，为什么比另一个选择好，会放掉什么，看到什么就改**。 宿主锁住比赛、时刻和队伍。模型提出选择并决定接下来要查什么。MCP 把可重复的查询和计算交给程序。一个模型就能开始做这个实验。[真人片段与取样边界](教练复盘取样_20261112.md) · [已有宿主与接口设计](AGENT_MCP_IMPLEMENTATION.md)

## 一回合从哪里开始，到哪里结束

小汤宝讲入侵时，在草里给队友反应时间，看到队友开始靠才出去。稍后目标没闪，但队友被卡，他又准备撤。楚钧讲塞恩支援时，塞恩抓住剑魔仍在清线、兵还没进己方塔的时间先去了中路。由此，一回合可以从“这波线给了我一个选择”开始，也可以从“旧选择的必要条件刚刚消失”开始。同一时刻，中单的接线窗口、打野的入侵窗口、辅助能支援的窗口可以不同。[小汤宝等队友靠](https://www.bilibili.com/video/BV1fRrJYwEAe/?t=165) · [楚钧讲塞恩先动](https://www.bilibili.com/video/BV1fAJ6z3EKG/?t=543)

| 顺序 | Agent 此刻要回答的问题 | 宿主保存的可检查结果 |
| --- | --- | --- |
| 1. 暂停 | 上回合想换到什么？刚刚出现的事，影响哪个人、哪个目标？ | 本队当前能见的事实及时间、旧计划的目标和退出条件。玩家是否执行旧计划单列。 |
| 2. 提出选择 | 我现在有哪两个真能做的动作？也考虑放线先走、等下一波、收一部分资源或交换另一侧。 | 各写一句，给出第一步、代价、依赖谁、做完后的位置或状态。 |
| 3. 找分歧 | **哪条新信息最可能让我在两者之间改选？** | 例如“打野能先到，但中单会不会被线拴住”。有答案就引本帧证据，没有才调用一次能区分两种选项的工具。 |
| 4. 检验反例 | 对方怎么拆我的计划？若队友不来，我的退路还走得通吗？ | 比较双方到场、控制与脱离、兵线或购物代价。移除最重要的一项条件，区分“可以试一步再退”和“一旦进场必须打完”。 |
| 5. 封存与重开 | 现在该怎么做？什么变化值得再看？ | 保存首选、备选、证据 ID、改选信号。新的可见人、队友改向、兵线进塔或窗口到期才重看相应分支。后来发生的事进入单独的回看记录。 |

当工具仍答不出关键问题，模型可以给低成本的第一步和两个条件分支。举例说，“先发信号并在己方可接应处等，看到中单脱线靠过来才进”比“队友应该来”更接近可执行的复盘。模型输出只需保留与取舍有关的依据。

## 哪些计算值得做成 MCP

工具按教练会问的问题命名。一轮查询返回答案、时间与单位、适用范围、证据 ID、会让结果失效的条件。数值条件缺失时返回未知。本次只在下表第一项接通了新的 MCP 传输，其余项是可复用现有代码的实施顺序。

| 教练的问题 | 程序负责 | 模型负责 |
| --- | --- | --- |
| 对面谁露了？上次在哪，隔了多久？ | **已实跑** `enemy_sightings`。每人返回本队显隐、最后可见的路径首点、样本时间和年龄。未知保留空值。 | 说明是哪一个威胁改变了，决定下一问查哪条线、哪个入口。 |
| 现在走，还是接完线再走，谁先到？ | 下一项。复用兵线分组、位置与计时准入，分别算直接走和处理兵线后走的完成区间。多人的可到时间分别返回。标明可见移动、已观测响应、仍需猜测的条件。 | 比较先到换来的地图收益与漏兵、暴露路线的代价。判断打野等中单是否值得。 |
| 到了以后能做成什么，能否只拿一部分再退？ | 分开查队友衔接、敌方脱离、本人可退出路径、资源或拆塔所需时间。目标存续或技能状态有分歧时并列场景。 | 比较两个合理选项，决定是否值得提前到场，以及有没有足够战力接战。 |
| 现在回，还是多吃一波再回？ | 比较可核的购买门槛、兵线进塔与补给后再到场的窗口。用两个分支分别计算残塔能否撑到回推。 | 权衡本回合损益与下一回合装备、位置的价值。 |

**计算优先算会翻转结论的量。** 给定同一起点，方案 A 的到场时间是出发时间加路径耗时，方案 B 再计入实际要处理的那组兵和可能改变的出发位置。区间计算须注明地图、路径、移动速度和兵线依据。若两方案到场区间重叠，指出最可能改变先后的条件。若换一两次兵弹就会让残塔倒掉，只算这个边界即可。Inspired 指导悟空留塔回城的原例中，两只远程兵最终拆掉了塔。[留塔原片](https://www.youtube.com/watch?v=cn29K2aiHPI) · [相关字幕](https://prepublish.ai/youtube-transcript/cn29K2aiHPI#:~:text=Leave%20the%20tower%20alive)

## 自建时最值得投入的三个地方

1. **固定权限和时间，把战术查询交给模型。** 宿主先验证原件和本队前缀，绑定一帧，再启动本地只读服务。工具不接受对局路径、敌方视角或任意时刻参数。对外使用明确的输入、输出 schema。握手、列工具、调用、业务错误、关闭都留记录。语法合法后还要核对事实的视角、时间与引用。协议传输直接与本地函数比结果。[Agent 与工作流边界](https://www.anthropic.com/research/building-effective-agents) · [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) · [初始化与关闭](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)
2. **开场给选择所需的摘要，旧证据可以原样取回。** 按事实编号查原文适合审计，实战开场还需要能直接问“谁露了”。宿主保留完整事实，显示层可折叠前一帧的重复明细。取回一条历史记录后仍带历史时刻和原 ID。预算耗尽时提交有条件的建议与缺证，不重复请求同一记录。[工具粒度与返回内容](https://www.anthropic.com/research/writing-tools-for-agents) · [上下文组织方法](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) · [长上下文位置效应原论文](https://aclanthology.org/2024.tacl-1.9/)
3. **把“查错了”与“拿到证据仍判断错”分开。** 同一回合先验证程序能交付关键证据，再看模型是否主动查到、拿到后是否正确影响候选排序。如果把全部相关且合法的证据直接给模型仍然答错，应优先改行动比较、提示或评判规则。只有程序确实供不出决定性事实时才登记数据缺口。[ToolSandbox 的中间状态与禁止状态](https://arxiv.org/html/2408.04682v1) · [多轮 Agent 评测方法](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

## 真实回放里，这样分析有什么不同

**16.22 十人局，蓝方潘森。问题限定为“能否凭眼下的敌方动向，支持自己单人进河”。**

- **05:00** 蓝方看得见卡特琳娜，位置样本距今 0.06 秒。剑圣不可见，最后一次采到位置已过 100.32 秒。塔姆也不可见，但他的样本仅过去 4.63 秒。我的建议是暂缓单人探无视野依据的入口，先在有人可接应的位置等确认，代价是让出抢先落位的时间。如果剑圣重新露头，或队友实际开始接应，就重看进河方案。证据为 `f_35a8da21d05c042d6658`、`f_6c7143fcfde0e73464c4`、`f_8a1a15086c6159bccdf0`。
- **05:20** 蓝方已看到五名对手。剑圣的位置样本为 [11594, 1402]，塔姆为 [12360, 1584]，都约 0.10 秒前。旧条件“等剑圣露头”已经满足，继续这样提醒会误导玩家。此时可以给下半区队友报位置，区分要争的是上侧还是下侧入口，再查相应的己方接应与路线。仅凭这张视野帧，无法保证进河安全或队友一定到场。证据为 `f_26c770bcaea1a57f3c1c`、`f_7d92fcc685cd5dd8f1bd`。

## 本地模型拿到这些证据后，实际答对了吗

在同一台机器上用已有 `llama3.2:1b` 做了四次真实调用。每次新开对话，询问同一件事：蓝方现在看得见剑圣吗，最后一个位置样本及其事实 ID 是什么，仅据这些显隐观测能证明河道入口安全吗？固定中文问题、输出 schema、温度 0、种子 17、上下文 16,384 和输出上限 200。05:00 先给完整帧再给查询结果，05:20 交换顺序。查询结果由宿主选择并注入，测的是读证据能力，模型在本题中没有自行选工具。[Ollama 聊天接口与用量字段](https://docs.ollama.com/api/chat) · [结构化输出](https://docs.ollama.com/capabilities/structured-outputs)

| 蓝方帧与模型输入 | 服务报告的输入 token | 实际答对的字段 | 实际错误 |
| --- | ---: | --- | --- |
| 05:00 完整帧 | 5,898 | 0/4 | 报剑圣可见，给出卡特的位置和一个控制守卫的引用，还判断入口安全。 |
| 05:00 显隐查询结果 | 549 | 2/4，最后位置、引用 | 读到了剑圣 100 秒前的正确样本，仍答现在可见、入口安全。 |
| 05:20 显隐查询结果 | 559 | 3/4，显隐、最后位置、引用 | 五名对手可见，仍不足以证明入口安全，模型却答能证明。 |
| 05:20 完整帧 | 5,923 | 2/4，显隐、最后位置 | 位置引用错误，又判定入口安全。 |

这四次输出都符合 JSON 形状，但给玩家使用前都应拦下。我为这道题补了可运行的 `check` 校验，按宿主选定的敌人和原帧核对显隐、采样坐标、证据 ID，并拒绝仅凭此工具声称路线安全。将四份真实模型输出重新送检，四份均被拒绝，错误字段与上表一致。这项校验只覆盖这四个结构化断言。若模型写自由文本战术评价，仍须查实际引用、退出条件及上下文。

原始响应、模型摘要、输入摘要、逐字段判分和本地复现脚本保存在 `data/private/agent_study_current/`。本轮是一个小模型、一场十人局、两个时刻的定点读数。首轮含加载，后续有缓存，未比较速度。完整回合建议由模型自主取证、相邻卡片承接、不同对局的战术质量都留待另测。

## 下一轮怎样决定要不要换用新方案

| 只改变一个变量 | 通过什么判断 |
| --- | --- |
| 同一模型、同一冻结帧、同一预算。A 给现有完整输入，B 仅将历史明细替换为上述可查询目录 | 首先核实两组都能找到旧目标和改变它的事实。记录每次真实调用、取回哪些证据、模型用量和耗时。首个问题是缩短后有没有漏掉该改选的理由。 |
| 在胜出的输入方式上比较有无“接线后再走/直接走”的计算，随后单独引入一次“队友不来”的反例 | 小白的三选一、Hector 的巢虫、Bin 的回推线可作出题模板。给同一场景只改一项可见前提，看建议是否有理地改选、降为条件式或保持。 |
| 评判与回归 | 同一局的所有时刻归入同一组，另留完整未见对局。硬检查拦未来信息、错队、假引用和把旧建议当作已执行。战术盲评随机展示两张卡，比较可执行性、放弃的收益和改选条件，允许平手和多种合理行动。保留漏触发的回合。胜负与后来的击杀只用于回看。 |

**本轮决定**是由程序核定并呈现硬事实，模型负责比较行动。下一项用已有回放做完整回合对照，评估模型能否找到会改变选择的条件。战术质量仍待独立评阅。执行入口见[运行手册](../../README.md)，完整回归与版本见[状态记录](../../reports/STATUS.md)。
