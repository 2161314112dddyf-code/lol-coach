# 这波要不要打，打到哪一步该停

个人复盘遇到开打、换血、追击或保人时，大模型要替这名玩家判断：**我这轮需要做到什么，我能活着把关键一击打出来吗？** 战斗结束后的击杀公告只用于回看结果。判断开打是否合理，要用开打时本人和队伍可知的证据。

## 模型要做的三个判断

1. **这轮需要谁补哪一下。** 先定目标和时间窗口，例如“泰坦控住烬，到烬能重新走位为止”。若目标是击杀，先看受击时的血量、能吸收本次伤害的盾和来得及生效的治疗，再扣掉队友在这段时间能接上的输出，得到本人需要补的量。队友还在赶路、控制可能被兵挡、技能可能落空，就单列“如果他接上”的分支。若逼退对方就能保住射手或拿到线权，也要考虑在这里收手。
2. **双方哪一个动作先改变结果。** 从本人第一次能命中开始，排到下一次关键伤害、敌人的控制或脱离、队友到场。技能总和足够，也可能在第二段前被打断。反过来评估自己时，看谁能打到你、你要承受多久、保命技能是否仍在、哪里能退。能确认对手先控，就可以建议等控交掉；要断言对手先杀，还需要覆盖本人血盾的来伤依据。时序可判断时直接说谁先手，秒数没有依据就保留先后条件。
3. **哪一个现场信号值得改选。** 比较“现在打、等对方或队友先交一手、就此撤出”，挑出最改变结果的一项。开打前可以留技能；已经交位移或落地，就给这个位置上仍能执行的退法。给玩家说清首选、理由和改选信号，无须展示整张计算表。

工具负责查询已有证据，包括所选技能在特定条件下的伤害、距离与时间。大模型负责选择有意义的对照、判断谁有输出时间，以及缺项会不会改变选择。读数充分时给剩余血量或合理区间；证据较薄时可以给“这波需要队友再接一段，我一个人收不了”的条件判断。目标当前血盾都未知时，不宜凭空断言还差一发普攻。遇到未知仍可给动作，例如保留进场技能，先看前排能否留住人。当前伤害 MCP 绑定本人攻击敌方；估计反打风险要另看敌方可见动作，不能把本人的伤害公式倒用。

## 潘森 07:28 的应用

完整答卷又核算了较高血量下潘森能独立完成多少输出，并分别给出起飞前、落地后的退法。[07:28 玩家建议与实跑结果](../../reports/潘森交战判断_20261117.md)

**先看泰坦能不能把烬留下，再决定要不要飞。** 当时潘森距协助标记约 4,500，在 R 的 5,500 范围内。泰坦距标记约 1,000，伊泽瑞尔约 2,600。可以考虑泰坦先手后的那段输出，伊泽的第一轮尚不能预支。能封住退路、落点又在泰坦可接应的一侧，才值得把大交进去。[本帧证据](../../data/private/reasoning_sessions/combat-runes-20261116-release/01/evidence.json)

伤害工具可以回答一个具体追问。**假设**烬受击前是 300/1,000 生命、有效魔抗 40，一级 R 中心命中，期间没有其他伤害或治疗。无盾时落地后还差约 **69** 点血；有 50 点通用盾时还差约 **119** 点。这里使用已经扣盾的掉血，剩余缺口不再加第二遍盾。这个例子说明为什么要看泰坦能否接上，也说明实际血线未知时，不能把任一数值写作本局事实。R 后的下一发基础技能须按强化状态判断。[同一冻结帧的两次 MCP 对照](../../data/private/fight-design-20261116/two-shields.json)

本人此刻约九成血，但独自落在烬和卡尔玛面前时，对方有机会先拉开或集火，你可能打不出用来收尾的下一手。现有输入不足以量化谁先死。若泰坦落空、烬被加速带离中心，起飞前留 R；已经落地就回靠泰坦，放弃独自追进塔。能逼走下路，也可以结束这轮追击。

## 怎样验收模型的判断

| 只改变一件事 | 玩家应该看到什么变化 |
| --- | --- |
| 烬的起始生命固定，只增加 50 点完全适用的盾 | 在上述算例中，中心命中后的缺口从约 69 变成约 119；模型交代这多出来的一段谁有机会补 |
| 己方伤害保持足以击杀，敌方控制从我出手后改为我命中前生效 | 建议从出手并撤离，改为先躲、等控制交掉或放弃。反打数值未知时，只断言有依据的打断和集火风险 |
| 队友仍在附近，把“控制已命中”改成“正靠近，尚未命中” | 去掉默认能接上的输出，指出玩家该等的动作；若是保人局，也比较守住队友的收益 |

第二项另做了合成读题。目标剩 160 血、无盾，本人半血，技能 0.4 秒后造成 180 点伤害。甲场景中队友已控住目标 0.8 秒，敌方干预赶不上，退路可走；读者选择立即出手。乙场景中敌方已经起手，0.2 秒后会打断站定施法，侧退可躲；读者选择先侧退，再找机会。两题都能算出伤害足够，只有甲能确认在该窗口内打出来。乙的敌方集火伤害未经核验，读者保留了能否存活的未知。时间和血量为构造输入，此项是模型读题对照。

正式个人复盘通过 `model_messages` 把这项任务交给模型。第一步写在 `immediate_action`，伤害缺口与生存依据写进 `recommendation.why`，改选信号写进 `switch_conditions`。整局摘要在 `macro_round.enabling_condition` 保留最影响选择的一句。现有格式校验仍不能判定一句“能杀”在战术上是否成立；验收要看上面的条件改变时建议会不会随之改变。
