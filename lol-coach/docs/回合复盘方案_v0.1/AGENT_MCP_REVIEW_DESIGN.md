## 先看一个回合

**5:00，蓝方厄斐琉斯还要不要继续往前走？** 在已有回放里，刚才的外塔已经观测到零血。前面一组只有 3 个己方远程兵，后面的 6 个还隔着一段距离。剑圣重新出现在己方视野。此时我希望 Agent 给玩家的答复是：

> 这波先停在能和保护队友接上的位置。原来要点的塔已经零血，前面能跟的是三个远程兵。先看下一目标、保护队友和退路。兵线接上、队友到位，再考虑短压；保护跟不上，就放掉这次前压。

到了 **5:20**，厄斐琉斯本人出现零血观测。旧计划里“我可以现场输出”这个前提已经失效。新卡转为等恢复行动，再看能否补给、往哪集合。5:00 的建议在看到 5:20 前就冻结。若要追问“刚才是不是走深了”，需另查玩家实际走位，以及当时能看到的威胁。两张卡和结局时间相邻，不能据此归因。这两帧来自既有单线样本；峡谷三路线、打野和回城另用对应场景验收。[原局结果与两张卡](../OFFLINE_FINISH_RESULTS.md) · [样本地图依据](ROUND_REVIEW_EXAMPLE.md)

从这一例出发，第一版值得做的能力是：**记住上一条建议靠什么成立；新事实来了，能指出失效的是目标、时机，还是执行这件事的人。**

## 一回合怎样跑

1. **选一个值得暂停的时刻。** 程序维护每位相关玩家自己的目标和行动条件。本人或目标失效立即重看；兵线推进、威胁重新可见、关键资源将至也可能打开原来没有的选择。保留定期回看和未选时刻抽样，防止只盯旧计划、错过主动机会。
2. **锁定当时能知道的事。** 宿主选定回放、版本、观察方、玩家、截止时刻，冻结帧。英雄静态机制、最后可见记录、位置估计、当前观测各有标记。单独保留队伍当时可知与玩家是否实际注意到的差别。
3. **写出真正有分歧的选项。** 例如“现在走”“吃完线再走”“守住这波”。每项写第一步、想换到的收益、对手最有威胁的一种合理回应、队友要做什么、结束时自己在哪。备选选在什么情况下更好，退路则需在首选失败时依然能执行。
4. **只查会改变选择的信息。** 先用确定事实淘汰已失效的目标，再查会颠倒排序的量。若两种可能下都该停，停止查询。若“队友已经到位”和“队友还在清线”会给出相反建议，就优先查他的可见行动；仍未知时，给玩家一个可观察的转换条件。
5. **冻结建议，再复盘实际执行。** 第一张卡写“现在做什么、看什么信号改选”。回看层随后对照实际动作、后果及前一准备回合，区分选择、执行、信息变化和证据不足。只有找到当时可行的替代动作，才把问题归到更早的决策。整局最后挑一两条下局能用的提示。

## 程序具体算什么

| 问题 | 程序的输入与输出 | 现阶段处理 |
| --- | --- | --- |
| **这波有哪些兵真能用？** | 按线路、方向、空间分组统计己方视野内有存活依据的兵种、数量、已知生命、位置估计和最近掉血。将当前争夺点附近的组和后续组分别呈现。 | 已有分组和可知状态可用。到塔时刻、精确仇恨、隐藏兵、下一次补刀归属各自需要额外证据。[兵线结果](../LANE_WAVE_RESULTS.md) |
| **来得及做完哪几步？** | 对出发前清线/清野、赶路、到场准备、目标处理分别取有依据的耗时区间，输出到位区间、剩余时间、赶不上时应取消的步骤。留撤离时间的方案也把撤离列为一步。 | 路线与速度、操作条件和实测绑定后才可数值化。改令、变速、死亡、失去持续可见性时重算或作废。实局 ETA 尚待现有 T5/T6 准入。[计时验收](../ACTION_TIME_TEST_TASK.md) · [失效处理](../TRAVEL_VALIDITY_RESULTS.md) |
| **谁来得及，而且来了有用？** | 对每位相关英雄分别记脱身条件、到达区间、可执行动作、技能/资源前提、是否已观察到响应。会合取各人的最晚准备完成时间，再看控制、伤害或保护窗口能否重叠。 | 可用本局阵容和版本机制解释配合；动态施法、精确冷却、保护者承诺均需独立证据。人数下界只计已确认满足条件者；证据太少时给名单和条件。 |
| **多走这一步会丢什么？** | 两个方案从同一帧起算，比较可见兵暴露数量、经验/金币可得范围、延后营地、暴露路线、补给机会、下一回合位置。队友为配合而漏线也记成本。 | 有单位身份和版本价值才折算金额；“可能放掉”与“已经漏掉”分别记。兼容版本的清野样本须匹配等级、装备、技能、惩戒和收尾状态。 |
| **对手怎样能破坏计划？** | 先查确定的威胁。对消失英雄保留最后观测的时间和位置；有合格地图与机动约束才算可达区域，给“可能在哪些入口出现”。路径、位移、回城等关键条件无法约束时放宽范围。 | 目前优先用目标可见/消失事件与条件分支。按区域证明安全、推算敌方精确坐标、为某条路线给出胜率，都缺相应证据。 |

**用一个能复算的例子说明倒推。** 以下是算法用的合成输入，单位均为从现在起的秒数。设必须完成站位的截止窗口为 [12,15]，直去并准备好需 [7,11]，先吃线会额外用 [6,9]。余量区间等于“最早截止减最晚完成”到“最晚截止减最早完成”。直去有 [1,8] 秒余量，吃线再去只有 [−8,2] 秒。因此若必须按时到位，优先直去；若能确认清线更快或对方推迟集合，再重算第二项。这个比较只解决时间可行性，能否安全进场仍取决于视野和双方职责。

各人的连续步骤区间相加；可以同时发生的步骤按依赖关系取最大完成时间，避免把队友的赶路与自己的赶路重复相加。共享同一状态的步骤用同一情形计算，例如把“对方已经回城”和“对方还在守线”分别算，禁止拼接互斥情形。遇到未知时反过来求**允许多花多久**。例如已有最早截止 12 秒、直去最晚 11 秒，若要在所设范围里保证赶上，额外动作最多 1 秒；只要证据足以排除这一点，就无须精确模拟每次平 A。它仍可能偶尔赶上，不能据此判成必迟。

区间还要写明性质。有机制依据的上下界可用于排除；实测分位数只描述对应样本，即使整段分位区间都在截止前，也要保留迟到风险。双方到场以后，再比较到达施法/普攻范围、关键技能就绪、输出能持续多久以及撤出条件。本人能到场、队友能开团、输出能接上分别验。

## Agent 和 MCP 怎样接现有代码

宿主沿用 `run_reasoning(bundle, generate)` 的有限调用和修订预算，选择检查点、冻结上一张卡、保存调用记录并执行校验。一个本地 MCP 服务封装现有 Python 函数，先用标准输入输出通信。服务端随调用校验本局、观察方、截止时刻和版本；只接受宿主签发的帧与对象引用。模型每回合得到当时帧及经核验的前卡，重新开会话，跨时刻仅传计划摘要和引用。回看结果另开会话，避免随后解释结局的上下文流回早先决策。[既有模型流程](REASONING_FRAMEWORK.md) · [MCP 架构](https://modelcontextprotocol.io/docs/learn/architecture)

| 拟定工具 | 输入 | 输出与失败处理 |
| --- | --- | --- |
| `get_reference` | 当前帧允许的资料 ID，可批量 | 复用已有版本化机制、阵容条件规则、经验查询；返回出处、适用条件和内容哈希。引用越界拒绝。 |
| `inspect_situation` | 帧、线路/单位、要回答的问题 | 只读当前分组、状态和观测变化，附事实 ID、观测时间、可知范围和误差。缺值返回原因。 |
| `compare_actions` | 同一帧的少量候选及步骤，引用目标、执行人与依据 | 程序核对目标是否仍有效、行动条件和冲突，输出已排除项、可比项、关键未知及证据。在通过准入的范围内才添加派生数值。 |

推进时钟、读原包、读取另一方视角、解锁后验、保存最终卡都是宿主职责。复用现有 `decision_contract` 校验事实值、引用、前卡与改选理由。允许多个合理选项；若证据不能区分，写出选择所依赖的条件和现在可执行的第一步。

## 哪些计算值得先优化

- **复用静态资料。** 本轮只读核对一局 34 份 `ready_final` 的 bundle 哈希，统计 `reference_library`。按“资料 ID＋规范化内容 SHA256”计，578 次出现只有 17 份不同内容，33 对相邻资料库完全相同。逐条紧凑 UTF-8 JSON 合计 942,922 字节，去重后的内容为 27,733 字节，未计引用开销。优先让宿主按哈希存一次、按当前帧授权取用。原系统已经按需发资料，这里的节省发生在本地重复存取；模型 token、延迟和费用要单独实测。
- **只有影响方案的变化才值得重新推理。** 为每个候选登记所依赖的目标、兵团、队友、威胁与时限。新事件只刷新关联项；证据过期、机会窗口自然关闭也要触发。另保留全局重大变化及定时兜底，识别新机会。优化前后逐帧比对同一前缀下的状态，验证增量计算与从头重算等价。
- **先排硬冲突，再比较代价。** 零血旧塔可以直接剔除；两条路线若服务同一目标、满足同样约束，且在所有已比较维度上一条都不差、至少一项更好，才可删去另一条。有取舍、未知或独有的下一步选择，就保留双方。队友跟进和对手提前到场可先各演算一个有依据的分支；结论不同才查更多资料。优先实现这些便宜的检查，再考虑做有校准数据的模拟器。

## 怎么知道值得换上新框架

保留两道容易答错的对照题。第一道只移动兵团分布，让整线总数保持相同，观察调度能否发现旧计划依赖的前排已经走散。第二道撤去“队友保护已到位”这个前提，要求退路仍由本人执行。现有 5:00 样例曾在结构检查通过后发现，积极前压的备选被写成了退路。这两题分别能揭出漏暂停和假退路。[修正记录](../OFFLINE_FINISH_RESULTS.md)

| 顺序 | 对照与通过条件 |
| --- | --- |
| 1 · 先保真 | 固定 5:00、5:20 输入和录制好的工具请求，现有 Python 直接查询与 MCP 返回相同可见事实、资料哈希和未知原因。交换视角、传未来时刻或伪造引用应被拒绝。改变 5:20 的输入不得改变已冻结的 5:00 输入和建议记录。 |
| 2 · 再验计算 | 对已交付兵线逐组复算计数；对合成时限验证正余量、跨零和必迟，注入改令、消失、死亡和失去地图绑定后旧数值应失效。目标塔零血只淘汰该目标，本人零血取消依赖现场输出的计划；无关事件应保留仍有效的选项。 |
| 3 · 检验有没有帮到玩家 | 先用同一模型、同一帧、资料和预算比较现有方案与“问题＋候选计算”方案，顺序随机，隐去方法和赛果。让评阅者选哪个首选可执行、哪个退路真能走、漏了什么对手或队友条件，并允许平手。按整局隔离开发/保留样本；不同模式、队列、角色分组。没有独立标签前只报告具体反例。 |
| 4 · 单独测效率和漏报 | 固定分析方法，仅替换调度/缓存。对同一批帧记录模型调用、重复查询、输入输出 token、每局耗时及单次 P50/P95，同时盲标选中与未选时刻，报告重要改选漏报和无效打断。单局 175 个时刻、34 个检查点、141 个未选时刻可作首批回放材料；多个时刻同属一局。若省调用却错过关键改选，撤回该优化。 |

**建议的第一个开发交付**：一条命令接已有的 5:00 和 5:20 冻结输入，一次生成两张可追溯的中文卡，以及“哪条条件失效”的对照。先接资料查询与目标/本人状态的确定性检查，再扩展兵线和动作时间；数值计时继续沿用现行验收。这个切片可以直接用已有回放启动。涉及战术优劣和国服推广的判断，留给后续带真实评阅的同场景对照。
