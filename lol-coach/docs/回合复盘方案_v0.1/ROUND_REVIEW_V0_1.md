**目标：输入一局回放，按玩家的一次次行动回合，解释当时有哪些机会、应该怎么选、什么时候该收手，以及怎样为下一回合创造条件。** 保留现有解析成果，下一阶段重点转到分析链路。

## 1. 我建议怎样理解“回合”

一个回合，是围绕一个阶段目的展开的一段行动：**准备 → 作出选择 → 执行 → 转化收益或止损 → 重新部署**。发育、守线、撤退也可以是这一回合的目的。

- **开局依据**：新兵线/营地、回补后出门、关键技能恢复、对手减员或露头、目标争夺开始准备等，使行动选择发生实质变化。
- **结束依据**：收益已转化、状态不足、机会消失、被迫撤退/死亡，或者新信息使原计划失效。回城是常见节点，但不是唯一节点。
- **三个尺度**：整局的阵容取胜条件；本回合的资源和行动安排；回合内的技能交换与局部决策。不同玩家的回合异步，同队也可能有人能进攻、有人必须回补。
- **“轮到我做事”必须有依据**：兵线、状态、技能、位置和队友共同提供行动空间；不能只看人数或经济领先。

这是本项目对多份资料的操作性归纳，并非所有主播共同使用的严格定义。原采访中，Isles建议在回补节点暂停复盘，思考下一站与可完成的事情；Santorin强调打法要随双方阵容和取胜条件改变。[Isles原采访](https://dignitas.gg/articles/season-14-support-changes-with-dig-isles)、[Santorin原采访](https://dignitas.gg/articles/the-big-three-jungle-concepts-with-santorin)

## 2. 整条处理链路

| 环节 | 实际做什么 | 留下什么 |
| --- | --- | --- |
| ① 固定输入 | 回放、玩家、地图模式、版本、来源 | 可重复的运行记录 |
| ② 还原局势 | 事件与状态时间线；全知资料和当时可知资料分开 | 带时间、可见性、证据的快照 |
| ③ 接入基础 | 查地图路线、行动耗时、双方英雄机制、条件经验 | 本回合适用的事实与限制 |
| ④ 划分回合 | 程序找候选边界；模型说明目的与转折 | 连续的回合目录、关键决策点 |
| ⑤ 比较行动 | 对比实际选择与另外1—2项可行行动 | 收益、耗时、代价、后续状态、退出条件 |
| ⑥ 核对答案 | 查事实引用、版本、时间、可行性与条件 | 通过的建议，或明确的条件结论 |
| ⑦ 赛后解释 | 决策先冻结，再看后来发生了什么 | 区分决策、执行、对方应对与结果 |
| ⑧ 汇总 | 每回合一张短卡，整局只突出最值得改的3件事 | 中文报告＋可追溯JSON |

判断核心是：**移动、执行、退出所需的时间，是否装得进机会窗口；做完这件事后，下一个位置和资源状态是否仍然合理。** 缺少精确条件时给分支建议；只限制受影响的结论。

## 3. 模型具体怎么用

先用一个通用推理模型做“分析员”：读取结构化快照与已核验的历史，调用基础查询工具，检索相关真人案例，然后比较行动。程序负责状态、过滤、计算与硬性检查；模型负责解释、条件组合和建议。

同一时刻先写下判断，再开放后续结果。模型可以在新信息到来时改计划；每次改变要说明是哪条信息导致。知识库按版本更新，不指望模型参数记住所有地图、英雄和对局规则。检索的技术依据见[RAG原论文](https://arxiv.org/abs/2005.11401)；它不保证游戏判断正确。

## 4. 验收到什么程度就算这一阶段完成

建议首批以**峡谷打野视角**验收，但必须考虑三路队友与对手；其他位置沿用结构，分别评测。先冻结10局、50个参考回合，覆盖刷野/抓人、兵线/转线、资源争夺、撤退/回补。

| 验收项 | 建议门槛 |
| --- | --- |
| 当时可知 | 隐藏与未来信息泄漏0例；所有具体事实/计算可追溯 |
| 回合识别 | 50个参考回合至少找对45个；重复、乱切同时受精确率约束≥90% |
| 战术答案 | 至少40/50被人工判为可执行且理由充分；容许多种合理答案 |
| 硬伤 | 错版本、做不到的动作、编造状态等关键错误0例 |
| 交付 | 整局可运行，失败有记录；暂定整局处理P95≤10分钟，成本逐局记录 |

详细判分、反例和分母见[验收规格](ROUND_PIPELINE_SPEC_V0_1.md)。这些是**待批准的阶段门槛**，没有在本轮跑成，也不能由已有449项解码测试替代。不以“和主播逐字一致”或“后来赢了”判断正确。

## 5. 训练模型的规划

| 阶段 | 做法 | 进入下一阶段的依据 |
| --- | --- | --- |
| A：先用起来 | 通用模型＋工具＋检索；用100个开发回合建立标注规则、找错误类型 | 知道错在事实、检索、切分还是判断 |
| B：积累监督 | 收集有使用权限的复盘，整理局势、选项、理由、反例与退出条件 | 标签一致，能组成独立测试集 |
| C：针对性训练 | 先试切分/检索排序；若分析方法仍反复失误，再做监督微调（SFT） | 同一盲测集优于A，硬伤不增加 |
| D：偏好优化 | 用专家对两份答案的选择做偏好训练（如DPO） | 偏好可靠，改善的是决策质量而非文风 |

训练的是**如何用事实做判断**。初步可预算1,000—3,000条复核后的回合样本做小规模试验，实际数量由学习曲线决定；本轮不启动训练。暂不从零训练大模型，也不以不可靠模拟器做强化学习。训练数据划分、模型选择和费用估算方法见实现规格。

## 6. 本稿建议批准的三件事

1. 采用上述回合定义，并保留“整局—回合—决策点”三个尺度。
2. 先做峡谷打野的完整报告；按冻结样本和上述标准验收，不再无限追加基础校准。
3. 先建立通用模型基线，再依据错误决定训练；训练启动和费用单独形成具体方案。

批准后首个实现切片是：在现有 `macro-snapshot/v1` 和 `scripts/analysis.py` 上，串起**回合目录 → 当时输入 → 行动比较 → 证据检查 → 中文回合卡**。不新增前端。

调研中已读的正文、未能读取的视频字幕，以及不能直接套用的旧版本经验，均列在[来源报告](round_review_research_20261023.md)。
