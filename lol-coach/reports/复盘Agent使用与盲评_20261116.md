# 自建复盘 Agent 的使用情况

这次用两种问题验收。第一，把国服红方打野潘森的整场比赛按本人当时能知道的信息重放。第二，同题给两位独立模型读者，一位只有冻结事实，另一位另拿到正式 MCP 算好的位置、时间与选项比较。模型是否给出可执行的下一步，由匿名评阅和赛后实证分别检查。

## 本人实战暴露的问题

| 暂停点 | 初次实跑 | 已改动的正式链路 |
| --- | --- | --- |
| 05:00 | 潘森已死，不能立即动身。 | 原版客户端同钟的本人状态进入决策帧。附近交战排序在本人死亡、本人位置太旧时停止，允许建议购买、沟通和选复活后的方向。 |
| 07:28 | 既不能从协助信号认定队友已经动身，也不能单凭直线距离否掉 R 支援。 | 读自己的 R 图标；MCP 计算己方近期位置、红方可见敌人与同一标点的距离。对红方下路，泰坦比伊泽更有先接应的条件。 |
| 07:43 | 初版通过格式校验，仍建议重新找烬进 W 范围。真实公开播报已记伊泽击杀卡尔玛、潘森击杀烬。 | 修复 16.22 原生适配器原先固定返回空击杀列表的问题。将击杀者、被击杀者加入双方共有的既有事实类型，按首次实际读到播报的时刻开放。前卡涉及的对手被击杀，会触发重新评估。 |
| 01:22 正在打蛙 | 仅按玩家离哪个坐标最近，会在本局开野时猜反两个营地。在打蛙期间直接套用通用清营时长也会误判。 | 打野的第三种走法改为收完已确认的营地。当前怪、剩余血和历史掉血速度单列。换到中单、辅助时仍用对应位置原有的比较方式。 |
| 22:15 | 同样是「协助我」，实际附近没有下路那样的接应。旧文字还错用了南河蟹锚点。 | 核对原生小地图和实际龙点，同一份红方帧同时提供标记区域、视野、附近采样和兵线。本人发信、队友运动、个人击杀小龙分别取证。 |

**07:43 重跑结果。** 首版读者的第一步是「重新看到烬进W范围再接控」。修复后换独立读者，从 00:00 重新开始。该帧 MCP 返回两个击杀事实，烬距被击杀约 1.66 秒，同时提示上个计划涉及的对手已被击杀。本次第一步变为「从下路往龙口靠，给泰坦和伊泽标龙，开扫描查入口」，并要求看见侧翼、有人接应、惩戒可用才开。这里能核实答卷随新证据改变，不能据此断定下一步一定该打龙。[首次封存](../data/private/reasoning_sessions/pantheon-red-full-20261116-v1/05/answer.md) · [修复后封存](../data/private/reasoning_sessions/pantheon-red-full-20261116-v2/05/answer.md)

个人红蓝范围、外部数据快照、前卡承接、只读 stdio MCP 和 `round-decision/v1` 都沿用项目原入口。自建宿主用文件交换接入了独立 Codex 读者，适配代码只负责取当前包、展开事实引用、校验和封存，战术内容由读者逐帧撰写。本机 Ollama 另行实测。两者不能合并计算通过率。

重跑原卡的标题用过「下路双杀」。逐条署名是伊泽、潘森各一杀，不能记作潘森个人双杀。给玩家的摘要已使用逐人归属。宿主如今在存在公开击杀的帧上也会提醒模型检查个人连杀称号的证据。原卡保留封存时的文字。

## 三个匿名问题

第一题取国服本局 07:28。第二、三题来自公开数据集的下一场完整比赛 `2877292_1`，此前工程检查用过的两场均排除。先固定蓝方打野和 05:00、10:00，再取数据。该场为 16.1 的悟空，保留己方可见字段和自己的经济；没有可靠的位置、兵线、营地存活和实时冷却。它检验换一场后的推理边界，国服 16.22 的原包兼容性另由本地实战验证。[公开数据版本](https://huggingface.co/datasets/zauberine/lol-winprob/tree/d10424fb53f7a74b22b75a0c751edb96425fb40d) · [范围、校验和与选局规则](../data/private/jungle-review-20261116/holdout/source.json)

两位读者逐张封存短建议，均未看结算和对方答案。第三位模型只见打乱标识的 X/Y 和当帧证据，按第一步、本人状态、队友/对手条件、机会成本、改选信号五项逐项核对。每项 0 或 1。

| 题目 | 只有冻结事实 | 另有 MCP 计算 | 评阅者的偏好及理由 |
| --- | ---: | ---: | --- |
| 红方潘森 07:28，值不值得飞下 | 5/5 | 5/5 | 有 MCP。先看泰坦能否接，再决定是否用 R，给出了空飞与等人的不同代价。 |
| 蓝方悟空 05:00，先刷还是转龙 | 5/5 | 5/5 | 只有事实。它把敌方打野是否在另一侧也列为转龙前的核查，比只等己方线权更完整。 |
| 蓝方悟空 10:00，怎样用本人的当前状态改路 | 5/5 | 5/5 | 有 MCP。它具体区分了 R 好时接控、R 冷却时继续刷；遗漏了检查上路兵线，回城代价也说得过满。 |

三题中有两题偏好有 MCP 的答卷，六张均未发现严重无据断言。三题来自两局，评阅者也是模型；这个结果不足以估计总体胜率或代替教练签字。位置和时间计算使下路接应更好解释；外局缺实况时，工具无法提供原始数据里没有的路线。[六张匿名答卷与原始评语](../data/private/jungle-review-20261116/holdout/judge/verdict.md)

## 本机小模型

在同一场未用于开发的悟空局，两帧分别用 `llama3.2:1b` 跑只带冻结事实和带正式 MCP 的宿主。两边都只给当时的同一帧、同一问题、温度 0、种子 17、上限四次模型回合。两组各 **0/2** 通过答卷契约。只读事实组出现三个走法没有分别给出可执行第一步；工具组仍出现只列数字、没有说明付出什么代价。未通过的答卷均未发作玩家建议。[只读事实 05:00](../data/private/reasoning_sessions/heldout-20261116-baseline-300/manifest.json) · [使用 MCP 05:00](../data/private/reasoning_sessions/heldout-20261116-tools-300/manifest.json) · [只读事实 10:00](../data/private/reasoning_sessions/heldout-20261116-baseline-600/manifest.json) · [使用 MCP 10:00](../data/private/reasoning_sessions/heldout-20261116-tools-600/manifest.json)

## 实际数据与复跑

两次独立模型实跑各 13/13 张通过同人、同队、同原件、时间递增、答卷契约及前卡封存顺序检查。每次各有 **55 次** 实际工具调用：地图计划 13、比较走法 13、敌方视野 13、读本人历史 11、查参考资料或队伍频道 5。23:09 新读者还结合三条队友被击杀播报取消了进河计划，改为回防。约 0.8 秒后游戏结束，不能把其建议的回城当成可执行结果。[首次封存审计](../data/private/jungle-review-20261116/v1-contract.json) · [修复后的封存审计](../data/private/jungle-review-20261116/v2-contract.json) · [原始完整玩家卡](../data/private/reasoning_sessions/pantheon-red-full-20261116-v2/review.md)

两轮封存后，另用两个相同时刻验收了 MCP 新增的本人移动指令、恒速走路算例和 R 射程比较。07:28 可区分「距标点直走约 12.9 秒」与「现有指令的终点仍离标点约 4,500」；22:15 只允许按 4.67 秒前的位置做历史算例。两次真实 stdio 返回与直接计算逐字段相等。这两次计时补测未计入前述 55 次调用。[时间计算、原包与反例](assist_travel_20261116.md)

- 原版客户端连续播放整局，保存 523 对时钟采样和 45 条事件。从 32 次英雄击杀重算的十人 K/D/A 全部与 ROFL 结算一致。播报没有列出本局小龙，个人小龙数在结算中单独核对。首次核账发现卡牌的显示名含空格，修正为稳定的英雄标识后重新连续采集。模型只取近 30 秒内已公开的击杀者和被击杀者，排除助攻、隐藏位置、结算及未播出的事件。[原版事件账本](../data/private/jungle-review-20261116/outcome/events-v3.json)
