# 公开回放数据能替代哪些对照实验

2026-11-11，HF-002，开发侧实际复跑。交付给玩家的步骤见[实验操作单](../docs/CURRENT_STAGE_EXPERIMENTS_20261101.txt)。样本选择、许可登记及字段来源见[前次调研](../docs/HUGGING_FACE_SOURCES_20261107.md)。本次以两个问题决定是否值得采集：开发侧能否用已有程序重现一个可核对的结果？仍缺的标签能否区分两个具体解释？

## 实测结果

| 检查 | 实际输入、干预与结果 | 对实验的影响 |
| --- | --- | --- |
| HF-1 两个时刻能否走现有输入链路？ | 固定分片的两局职业赛 `2877290_1`、`2877291_1`，分别有 1,934 和 2,126 个逐秒样本，构建均为 16.1.736.4955。各取 600 和 601 秒，分别以两方第一名选手为观察者。经研究脚本转换，再调用项目的 `compile_frame` 和 `model_messages`，8 份输入各有 48 条事实。第一局蓝方安蓓萨的血量从 1,221 到 1,225，第二局红方观察者从 1,484 到 1,461。 | **PASS，限定这两局的决策输入。** 可以用它们测换局、换视角、时间前缀和事实引用，无需人工逐秒抄 HUD。8 帧来自同一构建的 2 局，尚无战术优劣标签。 |
| HF-2 这些输入会泄露未来吗？ | 逐帧重建完整消息。改写截止时刻之后的英雄数据，消息逐字一致；再改动敌方当前状态、移除眼表和全局数组、改写赛果，消息仍一致。正对照中只让本人当前血量加 1，输出随之变化。证据可用时刻推迟 1 秒，现有编译器拒绝该输入。 | **PASS，限定这条转换路径。** 敌方仅保留开局身份及可见性未知；我方公开属性与本人经济使用白名单。此检查不能排除上游制作数据时的插补。七格物品与冷却列确实存在，但当前决策帧仍把完整背包、技能就绪标为未知。纳入比赛状态或把这些事实经 MCP 授权读取，需要另做适配和接口测试。 |

| CN-1 现有材料能否继续验证前后两张卡？ | 取国服冻结输入，核对输入文件哈希，从 293 秒的已验证回答开始，依次重建 300 秒、320 秒的帧，和留档逐一比对，重验旧答案均通过。第一次为改选（revise），第二次为取消（cancel）。将较晚的卡作为早先帧的历史，两次均按 `previous_time_not_earlier` 拒绝承接。 | **PASS，限定现有前卡承接与回答契约。** 可用这条链验证未来的 MCP 接入。本次使用留档回答，没有重新调用模型、启动 MCP 服务或举行战术盲评。 |

| CN-3 既有四局能否提供独立标签？ | 重跑[已有窗口核查](../scripts/audit_experiment_identifiability.py)。80 对命名活动中 4 对满足既定邻域隔离条件，79 对附近有资源样本，缺独立的成功/转好标签。474 条实时创建对象记录缺单一视野源和双方区域对照。另查旧版背包留档，唯一 `ec` 例与 3、4、5 三种槽位映射均相容。 | **INSUFFICIENT_EVIDENCE。** 只对选定版本和字段安排补证。新客户端采样不能决定旧版 `ec`；公开数据的眼位坐标、起止时间也不能确定整片区域可见性。 |

## 根据结果取舍

软件回归在仅含 Git 暂存文件的公开副本运行，使用现有项目环境和新临时目录，结果为 1,223 项通过（16.70 秒）。另用该副本的 HF 核验器读取相同私有输入，输出 JSON 与工作区首次最终结果相同。六份导航及实验文档的 67 个相对链接已核对，桌面与项目操作单正文一致。实局战术正确率和新 MCP 传输结果尚无本次测量值。

| 目标 | 已有材料先做什么 | 何时才采新数据、怎样判定 |
| --- | --- | --- |
| Agent 输入与工具 | 用 HF 双阵营、双时刻测试看不见的信息；用国服 5:00/5:20 做两帧业务基线。 | 当前无需录制。下一工程实验用同帧同参数比较 Python 与真实 MCP 子进程的合法查询，再故意提交另一帧或另一阵营引用。MCP 新产生的结果单独存档。 |
| 国服技能 S、移动 M | 已有 16.20 命名活动和移动片段保留。旧视频的一个完整走路样本可用，另一个片段缺清晰起步与绝对时钟；[已有视频核查](travel_evidence_attempt_20261101.md)。 | 目标构建有同局片段时先用。缺锚点时，只录 E00 中所需的动作；静置、成功、失败输入及自然亮起可共用一次技能周期。移动先区分自动到达、手动停止和改道，预留独立样本后才评到达误差。 |
| 国服背包 I、视野 V | 用旧服购买与换槽作软件回归。国服样本已有对象可见性与创建记录。 | 要判两个候选槽时固定物品、数量和可用状态，只换格；有剩余歧义才加第三格。要判区域视野时固定敌方位置，记录 A 方画面及 B 方位置，以无眼、单眼、消失三态作对照。只在开阔地基线成立后再加入草、墙或双眼。 |
| 兵线、营地、动作耗时 J | 已有国服可见兵线分组可使用，旧包有生成、身份和营地编号。 | 若具体分析依赖精确到场、逐单位交战或清野耗时，先补已有录像/条件匹配实测。仍缺时，只采对应路径或一个营地，保持英雄、版本、等级、装备、技能和操作条件可核对，记录实际开始、结束及剩余状态。 |
| 战术评阅 R01 | 两张已有卡可做开发反馈；留档 175 个观察时刻含 141 个未选时刻。 | 无需开游戏。另取没看过的对局，遮住后续结果与方法名称，先记录首选、退路、改选信号，再比较答案。选中与未选时刻都抽；无独立标签时保留未知。 |

## 复跑与证据

在 `lol-coach/` 目录使用项目 Python 环境。这项研究脚本另用 NumPy 读取 NPZ，本次版本为 2.2.6。只安装了公开基础依赖的环境，可在该虚拟环境执行 `python -m pip install numpy==2.2.6`。核验器接受固定的三个文件，按 SHA-256 校验后才运行，不向模型或仓库发送原样本。

- `two-games.tar.prefix` 为 [zauberine 固定分片](https://huggingface.co/datasets/zauberine/lol-winprob/blob/d10424fb53f7a74b22b75a0c751edb96425fb40d/shards/shard-0000.tar) 的字节 0–2097151，读取前两局的完整成员。配套文件是同一提交的 [features.json](https://huggingface.co/datasets/zauberine/lol-winprob/blob/d10424fb53f7a74b22b75a0c751edb96425fb40d/features.json)。
- 事件样本是 [maknee 固定分片](https://huggingface.co/datasets/maknee/league-of-legends-decoded-replay-packets/blob/04f9c7350e9ffcc689b731875ad9baf3ff6eaa6d/12_22/batch_001.jsonl.gz) 解压后的第一行，去除换行。行内第几个事件作为稳定次序键。两个源头的构建与整个国服回放分开记录。
- 实际使用的本机运行目录为 `data/private/hf_feasibility_20261111_cfb27335/`。`public-final.json`、`cn-chain.json`、`direct-opcode.json` 与 `cn-control-audit/report.json` 分别保存输入实验、国内前后卡、原包编号和窗口核查结果。前两局张量和原始事件只保存在本机。复核工具见[公开数据实验脚本](../scripts/check_public_replay_samples.py)。

```powershell
$run = 'data/private/hf_feasibility_20261111_cfb27335'
.venv/Scripts/python.exe scripts/check_public_replay_samples.py --prefix "$run/two-games.tar.prefix" --features "$run/features.json" --events data/private/hf_20261107/maknee-12_22-batch001-first-match.json
```
