## 已实现的处理链路

本次工程切片为 ROUND-AGENT-01。宿主从同局、同队、同一玩家、递增时刻的 bundle 开始。它可从同一原件补上己方各路小兵、基地出生节奏和己方英雄位置样本，然后锁住查询的分路、目标、拟协助秒数。每个时刻单独启动 MCP 子进程。模型决定要查哪些事实，给出三项走法、成本及退出条件。宿主验过证据 ID、时间区间与方案的对应关系、必要工具调用后才接受该帧。下一帧只能引用上一张通过校验的卡。前卡另存，玩家是否执行始终待证。

| 工具 | 用途与边界 |
| --- | --- |
| `compare_round_options` | 并列计算立即出发、在原地协助指定秒数后出发、清完本波再出发。分别给出出发、抵达、完成目标、返线时段和对截止时刻的判断。成对的有此人、无此人目标完成时间都存在，才计算此人能省多少秒。缺任一项则余量保留未知。 |
| `compare_help_duration` | 以同一帧追问其他拟停留秒数，单独返回短帮方案与适用于该时长的边际收益证据。原题的默认时长与三案不受查询影响。 |
| `review_round_plan` | 比较前卡依赖的队友、目标、兵线及新显隐证据。给出应重新比较的选项及事实 ID。共同目标的控制窗、两人的首次作用区间、范围覆盖与一次技能的实际命中分别检查。当前两帧无法回答所有这些问题。 |
| `enemy_sightings` | 按观察队伍读取敌方可见状态、最后一次看到的位置和年龄。 |
| `get_reference`、`read_history` | 读取本帧准许的经验资料或上一回合事实。取回来的历史观测不能当作当前观测。 |

对于“清完再走”，出发时刻需要玩家清这波兵的条件耗时。对于“协助五秒再走”，五秒来自比较题，是主动停留时长。若卡牌本来就不在能帮忙的位置，工具仍能算出五秒后的时钟，但不能断言这期间有人获得了帮助。工程对照会逐一移除所依赖的证据，检查只让相关结论回到未知。
